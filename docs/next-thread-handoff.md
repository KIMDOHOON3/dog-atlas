# 다음 작업 인수인계

> 기준: 2026-10-28. 수치·검증·배포 상태는 [프로젝트 상태](project-status.md)를 단일 기준으로 삼는다.

## 시작 순서

1. 프로젝트 상태, 제품 목적, MVP 범위, 결정 기록, 시각 지침과 `AGENTS.md`를 읽는다.
2. Git 변경 상태와 현재 작업 요청을 확인한다. 로컬 작업과 운영 배포 상태를 구분한다.
3. [코드 구조](code-structure.md)에서 수정할 기능을 찾고, 해당 테스트와 관련 문서를 읽는다. Next.js 코드를 바꾸기 전 설치된 `node_modules/next/dist/docs`의 관련 문서를 읽는다.
4. 실행 중인 서버와 포트를 확인한다. 예전 기록에 적힌 포트가 현재도 실행 중이라고 가정하지 않는다.

## 이어서 확인할 항목

- 로컬에만 있는 홈페이지·운동장 개선과 배포 차단 상태.
- 실제 모바일에서의 렌더링·터치 동작. 브라우저 모바일 모사 결과와 구분한다.
- 아직 점검하지 않은 견종별 유전 질환·권장 검사 원고. [검토 목록](audits/genetic-health-review-queue.json)과 [최근 보고서](genetic-health-second-review-2026-10-24.md)를 따른다.
- 자산 제작 기록은 이용 허락 또는 전문가 검수를 뜻하지 않는다. 보류 원고·제작 원본·출처를 미사용 코드로 취급해 삭제하지 않는다.

## 마무리

해당 변경의 lint·typecheck·테스트·빌드를 실행하고, UI 변경은 브라우저에서 확인한다. 현재 결론만 상태 문서에 적고 상세 이력은 별도 기록에 둔다. 커밋·배포 범위는 현재 사용자 요청과 적용되는 승인 상태를 따른다.
