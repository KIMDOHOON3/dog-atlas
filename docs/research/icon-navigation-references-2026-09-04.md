# 아이콘·레이아웃·검색·내비게이션 레퍼런스

> 조사: 2026-09-04
> 상태: 디자인 비교 자료와 적용 제안. 제품 구현·스타일 확정 전.

## 조사 목적

사용자는 토스·당근·배민처럼 개성 있는 아이콘과 편한 화면 배치, 검색, GNB를 함께 설계한 서비스를 참고하고 싶다고 요청했다. 시각적 개성과 인터랙션을 우선 탐색하는 방향을 유지하면서, 반복해서 사용하는 메뉴와 탐색 화면의 완성도를 함께 비교한다. DogPack 후보 1과 수채화 등장 연출 I-01은 유지한다.

## 먼저 비교할 대상

| 대상 | 우선 볼 부분 | 우리에게 던지는 질문 |
| --- | --- | --- |
| Airbnb | 큰 카테고리 아이콘, 검색과 콘텐츠의 위계 | 그림이 있는 메뉴가 어디로 가는지 바로 알려주는가? |
| 오늘의집 | 큰 서비스 메뉴와 세부 메뉴, 통합검색 | 도감과 생활 정보 사이에서 현재 위치가 분명한가? |
| First Choice | 일관된 실루엣의 아이콘과 테마 탐색 | 작은 그림만 보아도 같은 브랜드라고 느껴지는가? |
| 토스 | 아이콘의 시각적 무게, 메뉴의 간격·반응 | 크기와 글자 길이가 달라져도 편하게 읽히는가? |
| 당근 SEED | 상단·하단 메뉴, 선택 상태, 뒤로가기와 닫기 | 어디에 있고 어디로 돌아가는지 예측할 수 있는가? |
| 배민 | 검색 진입 화면의 콘텐츠 | 무엇을 검색할지 모르는 방문자도 탐색을 시작할 수 있는가? |

이 순서는 이번 비교를 위한 제안이며 사용자가 정한 후보 순위를 대체하지 않는다.

## 1. Airbnb — 검색과 카테고리 아이콘을 함께 보기

- [한국 웹사이트](https://www.airbnb.co.kr/)
- [2025 여름 개편 공식 화면·데모](https://news.airbnb.com/product-releases/airbnb-2025-summer-release)
- 2025 공식 이미지에서 큰 검색 진입 영역, 집·열기구·벨로 표현한 세 카테고리, 이름·밑줄을 이용한 선택 표시, 사진 카드의 저장 아이콘을 시각적으로 확인했다. 카테고리 그림과 작은 조작 아이콘의 표현 밀도가 다르다.
- 2026-09-04 공개 한국 홈페이지 텍스트에는 `전체 / 숙소 / 체험 / 서비스`와 여행지·날짜·여행자 입력이 있다. 2025 이미지의 세 탭을 현재 서비스의 전체 메뉴라고 단정하지 않는다.
- **적용 제안:** 도감·동반 장소·병원처럼 큰 목적의 메뉴에 자체 그림과 이름을 함께 사용한다. 검색 입력과 현재 검색 대상을 가까이 두고, 선택 상태가 그림 외에도 글자나 표시선으로 드러나게 한다.
- 이미지 사본: `tmp/design-reference-2026-09-04/airbnb-2025-official-navigation.jpg`. 현재 앱 직접 캡처가 아닌 2025 공식 공개 자료다. 공식 페이지의 영상 링크를 확보했으나 이번 조사에서 재생·모션을 직접 검증하지 않았다.

## 2. 오늘의집 — 메뉴를 단계별로 배치하기

- [웹사이트](https://ohou.se/)
- 공개 홈 문서에서 `집구경 / 쇼핑 / 인테리어·생활`, 통합검색, 그리고 `홈 / 추천 / 집들이 / 집사진 / 커뮤니티 / 3D인테리어`의 구분을 확인했다. 쇼핑하기·오늘의딜·집들이 등의 바로가기와 사진 콘텐츠도 있다.
- **볼 부분:** 큰 서비스 이동, 선택한 서비스 내부의 탐색, 콘텐츠 카드가 어떤 순서로 연결되는가. 전체 메뉴와 하위 메뉴의 역할을 구분하는 레퍼런스다.
- **적용 제안:** 사이트 전체 메뉴와 `전체 / 카페 / 공원` 같은 화면 내부 분류의 모양·위계를 구분한다. 도감의 크기 필터와 장소의 지역 필터가 같은 메뉴처럼 섞이지 않게 한다.
- 이번에는 공개 문서의 메뉴 구조를 확인했다. 현재 아이콘 외형, 고정 헤더·모바일 전환 동작, 자동완성·통합검색 결과는 직접 검증하지 않았다.

## 3. First Choice — 아이콘 자체가 브랜드의 일부가 되는 사례

- [웹사이트](https://www.firstchoice.co.uk/)
- [제작사 Ragged Edge 사례](https://raggededge.com/partnerships/first-choice)
- 제작사는 수영장·산·도시·바다 등 경험을 나타내는 아이콘을 중심으로 디자인 시스템을 만들었다고 설명한다. 공개 아이콘 이미지에서는 굵고 둥근 면, 단순한 실루엣, 반복되는 형태감과 제한된 색을 확인했다. 나무·텐트·발바닥·식기 같은 서로 다른 사물에도 같은 조형 감각이 이어진다.
- 현재 공개 홈페이지에는 Beach·City Break·Mountains·Family 등 테마, Shortlist, Recently viewed가 있다. 제작 사례의 과거 화면과 현재의 실제 조작 경험은 구분한다.
- **적용 제안:** 종이 위에 찍은 도장이나 오려 붙인 조각처럼 보이는 카테고리 아이콘을 하나의 시안 방향으로 비교한다. 수채화 그림과 어울리는 단순한 외곽, 모서리, 시각적 무게를 찾는다. 색상·스타일 채택은 미정이다.
- 비교 이미지: `tmp/design-reference-2026-09-04/first-choice-creator-icon-family.webp`. 제작사 공개 자료이며 제품 자산으로 사용하지 않는다.

## 4. 토스 — 아이콘과 작은 메뉴를 일관되게 다듬기

- [아이콘 제작기, 2023](https://toss.tech/article/1st-graphic-designer)
- [메뉴 컴포넌트 개선, 2024](https://toss.tech/article/toss-design-system)
- 제작기는 아이콘의 밸런스와 TDS 색상을 통일하고, 이를 3D·애니메이션으로 확장한 과정을 설명한다. 공개 이미지에서 비슷한 크기감과 제한된 색의 아이콘들을 확인했다. 현재 토스의 전체 아이콘 라이브러리를 조사한 것은 아니다.
- 메뉴 개선 글에는 긴 글자에 대응하는 너비, 선택 표시 위치, 스크롤 가능성을 드러내는 흐림, 등장·퇴장·터치 반응, 큰 텍스트·화면 읽기 대응이 설명돼 있다.
- **적용 제안:** 아이콘을 단독으로 고르는 것과 함께 실제 메뉴에 넣어 이름·여백·선택 상태를 비교한다. 작은 검색·닫기·필터 아이콘은 명확한 형태로, 큰 카테고리 그림은 더 풍부한 표현으로 검토한다.
- 비교 이미지: `tmp/design-reference-2026-09-04/toss-official-icon-system.png`. 2023 글의 제작 사례 이미지다.

## 5. 당근 SEED — 아이콘부터 내비게이션 정책까지

- [아이콘 가이드](https://seed-design.io/foundations/iconography)
- [Bottom Navigation](https://seed-design.io/components/bottom-navigation)
- [Top Navigation](https://seed-design.io/components/top-navigation)
- 아이콘 가이드는 로고에서 이어지는 형태, 부드러운 인상, 굵은 선과 단순한 모양을 설명하고 단색·멀티컬러 아이콘을 구분한다.
- 하단 메뉴 문서는 아이콘과 라벨, 선택 상태, 짧은 이름, 최대 5개 탭, 아이콘 스타일 통일을 다룬다. 이는 당근의 규칙이며 우리 사이트의 확정 규격이 아니다.
- 상단 메뉴 문서는 루트 화면과 상세 화면을 구분하며, 이전 단계로 돌아가기와 현재 흐름을 닫기의 의미 차이까지 설명한다.
- **적용 제안:** 모바일의 핵심 이동 메뉴에는 짧은 이름을 함께 표시한다. 검색 결과에서 상세를 보고 돌아왔을 때 검색어·필터·보던 위치를 복원하는 흐름을 시안 확인 항목으로 둔다.
- 당근 서비스 홈페이지 조회는 403으로 제한돼 이번 분석은 공개 SEED 문서를 근거로 한다. 실제 현재 앱의 모든 화면을 검증한 것은 아니다.

## 6. 배민 — 검색을 시작하는 화면도 설계하기

- [검색 홈 큐레이션 공식 설명, 2024](https://techblog.woowahan.com/17383/)
- 공식 글은 검색 버튼으로 진입한 검색 홈에 추천 콘텐츠를 보여주는 구조를 설명한다. 이 문서에서 참고하는 부분은 입력 전 탐색 화면의 역할이다.
- **적용 제안:** 검색 전에는 최근 검색이나 대표 탐색 주제를, 입력 중에는 분류가 표시된 후보를, 검색 후에는 선택한 조건과 수정 방법을 보여주는 흐름을 비교한다. 이는 우리 제안이며 배민의 모든 해당 동작을 확인했다는 뜻이 아니다.
- 개인화 추천 시스템이나 행동 추적 도입을 제안 범위로 확정하지 않는다. 공개 글의 과거 사례이며 현재 앱 홈의 카테고리·광고·메뉴 구성을 직접 검증하지 않았다.

## 우리 시안에서 함께 비교할 항목 — 제안

1. **자체 아이콘:** 큰 카테고리 그림, 작은 조작 아이콘, 선택·비선택 상태를 실제 크기에서 나란히 비교한다. 이름을 함께 읽을 수 있고 단색으로도 의미가 남는가?
2. **전체 메뉴와 세부 분류:** GNB는 주요 목적 사이 이동을, 화면 내부 탭과 필터는 현재 목적 안의 탐색을 맡도록 역할을 구분한다. GNB에 모든 분류를 늘어놓지 않는다.
3. **검색의 네 장면:** 입력 전 → 입력 중 → 결과 → 상세에서 돌아오기. 검색 범위, 결과 종류, 필터 해제, 빈 결과의 다음 행동이 분명한지 확인한다.
4. **화면 크기:** 데스크톱 상단 메뉴와 모바일 메뉴에서 같은 목적이 같은 이름으로 이어지는가? 실제 메뉴 개수·고정 방식은 레이아웃 시안에서 결정한다.
5. **수채화 연출과 연결:** 배경과 큰 그림에는 종이·수채화 분위기를 검토하고, 검색·메뉴 영역은 선명한 대비와 안정된 위치를 확보한다. I-01의 번짐 완료를 기다리지 않고 탐색할 수 있어야 한다.

기존 [제품 아이콘 가이드](../product-icon-guide.md)는 현재 자산과 구현의 기준으로 유지한다. 이번 조사는 그 가이드를 교체하거나 새 아이콘 스타일을 승인한 작업이 아니다.

## 확인 범위

공식 공개 웹 문서, 디자인 시스템, 제작진 사례와 이미지 3종을 근거로 비교했다. 직접 로그인하거나 모바일 앱을 조작하지 않았고, 검색 자동완성·조건 유지·스크롤 복원·전환 속도·터치 조작을 전체 검증하지 않았다. 디자인 평가와 적용 제안은 조사자의 판단이며 사용성 우위를 입증하는 사용자 테스트 결과가 아니다. Klook의 공개 메뉴도 조회했으나 이번에는 위 6개 자료로 비교 범위를 좁혔다.
