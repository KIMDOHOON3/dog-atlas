# 카드 셰이더 최적화 — 2026-09-05

사용자가 실제 사용 중 끊김을 보고했다. 그림/텍스트와 눈 결정·산 능선·홀로그램 기능을 유지하면서 렌더링 부하를 줄였다. 이미지 압축만으로 해결하려 하지 않고 매 프레임의 작업을 변경했다.

## 변경

- 7개 눈 결정의 거리 함수·삼각함수 반복, 산 능선·몸/얼굴 마스크·미세 무늬·노이즈를 빌드 시 계산한다. `scripts/generate-card-foil-map.mjs`가 384×528 RGB 데이터 맵과 256×1 색상표를 만든다. 이미지 생성 API를 쓰거나 원래 그림을 편집하지 않는다.
- 런타임 fragment shader는 텍스처 2회 조회와 움직이는 빛 계산만 수행한다. 각도에 따라 무늬를 드러내는 동작은 여전히 실제 WebGL이다. 정반사와 미세 반짝임은 더 가벼운 근사식이며 이전 모든 픽셀과 동일한 출력은 아니다.
- 카드 CSS 기울기는 최대 약 60회/초, 포일은 약 30회/초. 동작이 끝난 위치는 즉시 갱신한다. 고주사율 모니터의 RAF 빈도만큼 GPU 요청을 늘리지 않는다.
- 포일 캔버스만 CSS 픽셀 기준 최대 너비 320으로 제한한다. 1254×1254 원본 수채화와 HTML 텍스트는 유지한다.
- 매 프레임 이동하던 CSS radial-gradient를 정적인 테두리로 변경해 페인트 부하를 줄였다. 포인터 위치는 RAF에서 한 번만 읽고, 포인터 이동마다 React 상태를 갱신하지 않는다. 캔버스 크기는 ResizeObserver에서만 계산한다.
- 효과 끄기/강도 0에서 GPU 그리기 생략. 카드가 화면 밖이거나 탭이 숨겨지면 루프 중지. 텍스처·셰이더·버퍼 정리와 로딩 실패 대체 화면을 유지한다.

## 로컬 비교

Codex 내장 브라우저, 동일한 기본 viewport, `http://localhost:3002/card-lab?profile=1`에서 각 1회의 4.4초 빛 시연을 측정했다. `data-motion-profile` DOM 속성은 해당 query가 있을 때만 시연 결과를 기록한다. 일반 사용자 화면에는 측정 UI를 추가하지 않는다.

| 항목 | 변경 전 | 변경 후 |
|---|---:|---:|
| 시연 움직임 샘플 | 954 | 265 |
| 시연 중 포일 draw 요청 | 954 (매 샘플) | 132 |
| 포일 캔버스 크기 | 510×723 | 320×453 |
| 평균 움직임 갱신 간격 | 4.62ms | 16.67ms |
| p95 움직임 갱신 간격 | 8.3ms | 16.8ms |
| 33.4ms 초과 간격 | 0 | 0 |

GPU draw 요청은 약 86%, 한 번의 처리 픽셀 수는 약 61% 줄었다. 후자의 갱신 간격은 의도적인 60Hz 제한 결과다. 이를 FPS 향상 또는 GPU 실행 시간이 그 비율만큼 줄었다는 수치로 해석하지 않는다. 이 자동화 환경에서는 사용자가 보고한 심한 프레임 지연이 직접 재현되지 않았고, 실기기 GPU 시간·입력 지연 측정은 아니다. 실제 사용자 체감은 재확인이 필요하다.

## 검증

새 페이지에서 두 재질 이미지 로딩 성공, 무늬·그림·시연 유지, 브라우저 error/warn 없음 확인. 테스트는 240Hz 입력에서도 GPU 호출 상한 유지, 입력 안정 후 RAF 정지, 효과 끄기에서 GPU 호출 0건을 추가 검증한다. 전체 검사와 프로덕션 반영 결과는 프로젝트 상태 문서를 따른다.

최종 lint·typecheck·57파일/1,652테스트·403페이지 생성 프로덕션 빌드 통과. 390px 화면에서 드래그와 강도 0일 때 `data-foil=false` 확인. 카드와 두 텍스처 HTTP 200. 3001의 기존 카드 탭을 새로 불러와 `data-material-ready=true`, 캔버스 320×453과 카드 화면을 확인했다. 데이터 맵 186,447B, 색상표 858B가 추가됐으며 원본 수채화 파일은 변경하지 않았다.
