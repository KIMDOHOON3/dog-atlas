### 2026-08-25 역할 카드와 포메라이언 콘텐츠 정리

- 표준 상세 첫 화면의 `계통` 카드를 과거 역할로, 기존 역할 카드를 현재 역할로 재편했다. 역할이 이어지는 견종은 `과거부터 현재까지` 한 장으로 합치고, 홀수 카드의 마지막 항목이 전체 폭을 쓰도록 배치했다.
- 포메라이언은 저먼 스피츠 전체 바라이어티가 아닌 18~24cm 크기와 현재의 놀이·학습·알림·이중모 생활로 다시 편집하고 전용 현대 생활 삽화를 추가했다. 치와와의 안전 제목과 진돗개의 상단 문장·관계 설명도 본문에 맞게 고쳤다.

## 1. 한눈에 보기

Dog Atlas(살아 있는 견종도감)는 강아지를 고려하는 사람이 외모와 인지도만으로 선택하지 않도록 돕는 한국어 편집형 웹 도감이다. 사용자는 견종을 발견하고, 역사와 원래 역할이 행동 경향과 현대의 돌봄 요구에 어떻게 이어질 수 있는지 읽고, 자신의 생활 조건과 맞이 준비를 점검한다.

현재는 초기 5종 또는 100종 MVP 계획을 넘어 **376개 상세 항목과 시각 자산을 제공하는 로컬 데이터 기반 구현**까지 확장된 상태다. 마스터 카탈로그의 376개 항목 모두 상세 페이지가 있다. 등록단체 관계인 `registryStatus`와 도감의 편집 포함 근거인 `inclusionType`을 분리했으며, 골든두들과 말티푸는 등록 견종으로 오인되지 않도록 `designer-cross`로 표시한다. FCI가 한 견종의 네 바라이어티로 분류하는 벨지안 셰퍼드 독은 국내 탐색 편의를 위해 그로넨달·라케노이즈·말리노이즈·테르뷰런 네 상세로 나누되 동일한 FCI 표준 관계를 표시한다. 보어보엘은 KUSA·AKC 등록 근거를 명시한 FCI 미인정 견종으로 수록한다. 아나톨리안 셰퍼드는 AKC 등록 기준의 별도 상세로 수록하고 FCI 캉갈과 동일 표준으로 단정하지 않는다. 불개는 국제 등록 견종이 아니라 영주에서 기록·연구된 희소 집단으로 구분하며 전승과 유전 연구 결과를 분리해 설명한다.

## 2. 변하지 않는 제품 원칙

- 호기심과 따뜻함으로 사용자를 초대하고 책임 있는 판단을 돕는다.
- 견종 특성은 일반적 경향이며 개별 개체에 대한 보장이 아님을 밝힌다.
- 하나의 견종을 사용자의 정답으로 선언하지 않는다.
- 탐색과 관련 견종 링크는 특정 견종을 정답이나 추천 결과로 제시하지 않는다.
- 입양을 미루거나 후보를 다시 검토하는 것도 유효한 결과다.
- 편집 초안을 수의학 또는 행동 전문가 검수 사실처럼 제시하지 않는다.
- 모바일 우선, 접근성, 빠른 로딩을 장식적 복잡성보다 우선한다.

## 3. 현재 구현된 사용자 경험

### 홈 `/`

- 홈은 `외모보다, 함께할 생활을 먼저 살펴봐요.`라는 제품 관점을 첫 제목으로 두고, 이름을 아는 사용자는 기존 376개 자동완성 검색으로 바로 상세에 들어가며 이름을 모르는 사용자는 견종 발견으로 이어진다.
- 모바일 첫 제목은 `외모보다`를 작은 도입으로 낮추고 `함께할 생활`만 캐러멜색과 옅은 밑면으로 강조한다. 첫 설명은 필요한 시간과 환경을 확인하라는 한 문장으로 줄이고, 비어 있는 검색 오류 영역과 이미지 전 여백을 노출하지 않는다.
- 모바일 홈은 앞 섹션의 아래 여백과 다음 섹션의 위 여백을 겹쳐 쓰지 않고, 히어로·생활 조건·익숙한 견종·생활 관점 사이를 56px 단일 간격으로 통일한다.
- 첫 화면의 브랜드 비주얼은 재패니즈 스피츠를 중심으로 산책줄·물그릇·빗·산책 수건을 네 개의 모듈에 나눈 정지 3D UI 디오라마다. 흰 바탕, 코코아색 글자, 오트밀 표면과 절제된 캐러멜 포인트를 사용하며 단체 사진처럼 보이는 구도와 일반 이모지형 3D 카드 모음은 홈에서 제거했다.
- 생활 조건 진입은 차분한 활동·충분한 활동·낮은 빗질 부담의 기존 사실 필터 세 개만 먼저 보여주고, 전체 조건은 `/discover`에서 확인한다. 적합도 점수나 한 견종 정답은 제공하지 않는다.
- 모바일 생활 조건 진입은 반복 소제목을 두지 않고 `내가 가능한 생활`이라는 한 제목과 세 개의 생활 조건 카드로 구분한다. 각 카드는 한 문장 설명과 기존 사실 필터 링크만 유지하며 높이를 132px로 제한한다.
- 홈 생활 조건 카드의 대형 글자 장식은 대표 3D 스피츠 디오라마와 같은 재질·색조의 돌봄 오브젝트로 교체했다. 차분한 리듬은 방석과 목줄, 활동은 공과 로프 장난감, 관리는 브러시와 수건으로 구분하며 모두 투명 WebP 에셋을 사용한다.
- 생활 조건 카드 내부는 왼쪽 3D 모듈, 가운데 번호·카피, 오른쪽 이동 화살표의 가로 목록 구조다. 번호·이미지·화살표를 위아래로 흩어 놓지 않고 세로 중앙선에 맞춘다.
- 생활 조건 카드의 원형 이동 버튼은 그리드 행·열 중앙에 고정하고, 화살표 글리프는 글꼴 기준선으로 처져 보이지 않게 시각적 중심을 보정한다.
- 다음 영역은 푸들·말티즈·비숑 프리제·시추·진돗개·골든 리트리버 여섯 상세를 `익숙한 이름부터`라는 편집 시작점으로 연결한다. 인기 순위나 추천으로 표현하지 않으며 모바일에서는 손 스크롤 가능한 가로 목록이다.
- 익숙한 견종 영역은 반복 소제목 대신 `익숙한 이름에서 시작`이라는 한 제목만 사용하고, 전체 376종 링크는 작은 보조 버튼으로 둔다. 각 견종 카드는 이미지·한영 이름·원형 이동 표시를 한 구조로 묶으며, 마지막 생활 관점 카드는 `한 생명과 함께할 생활`을 캐러멜색으로 강조한다.
- 공통 상단은 브랜드·견종 발견·우측 메뉴로 단순화했다. 우측 메뉴 안에 `이름 속 견종`과 `견종 모아보기`를 두며, 모바일 하단의 주요 탐색은 `홈`과 `견종 발견` 두 개만 유지한다. 하단 바는 50px 터치 영역과 31px 아이콘을 사용해 안전 영역을 제외한 기본 높이를 약 55px로 줄였다.

### 이름 속 견종 `/breed-names`

- 대메뉴를 선택하면 별도 인덱스 없이 `Pointer` 상세(`/breed-names/pointer`)로 바로 진입한다.
- 상세 화면의 주제 내비게이션은 포인터·리트리버·세터·스패니얼·쉽독·셰퍼드·테리어를 한국어 주표기와 작은 영문 병기로 보여준다. 데스크톱은 한 줄 6열, 모바일은 모든 선택지가 바로 보이는 3열 2행으로 제공한다.
- 이름 유래 소개는 홈·견종 발견과 같은 중앙 정렬과 옅은 민트 방사형 배경을 사용해 의미 제목과 설명에 초점을 둔다.
- 이름 유래 상세의 큰 색상 패널과 대표 견종 이미지는 사용하지 않는다. 유래 설명은 의미 제목 바로 아래에 두며 견종 수와 `현재 도감` 안내는 표시하지 않는다. 결과 영역은 별도 `이 이름과 연결된 견종` 제목이나 선정 기준 설명 없이 카드 목록부터 바로 시작한다.
- `도감 / … / 현재 페이지` 형식의 경로 표시는 견종 발견·견종 상세·맞이 준비·이름 유래·견종 모아보기에서 데스크톱과 모바일 모두 표시하지 않는다.

### 견종 호기심 탐험 `/curiosity`

- 대메뉴를 선택하면 별도 인덱스 없이 기본 주제 `독특한 털` 상세(`/curiosity/distinctive-coats`)로 바로 진입한다.
- 상세 화면의 가로 주제 내비게이션에서 큰 체구·작은 체구·주름진 얼굴·이름 속 직업·도그쇼 이야기로 바로 이동한다.
- 주제 소개는 큰 색상 패널·견종 수·반복 설명을 제거하고 중앙 정렬과 옅은 민트 방사형 배경으로 간결하게 표시한다. 결과 머리글은 `N종의 서로 다른 이야기` 대신 주제별 선정 기준의 첫 문장을 제목으로, 나머지 문장을 보조 설명으로 사용한다.
- 데스크톱 헤더와 모바일 하단 내비게이션에서 두 편집 영역을 각각 독립된 대메뉴로 제공한다.

### 견종 발견 `/discover`

- 376개 항목을 체구와 여섯 개 tendency 축으로 필터링하는 독립 탐색 페이지
- 새 홈의 시각 언어를 이어 받아 흰 바탕·코코아 글자·오트밀 보조 면·캐러멜 행동색을 사용하고, 제목은 모바일 24px·데스크톱 28px 이내로 제한한다. `/discover`에서는 공통 헤더 면도 본문과 같은 흰색으로 맞추고 하단 선택 상태와 페이지 이동 버튼의 기존 초록색을 캐러멜 계열로 바꾼다.
- 검색 다음에는 한국 사용자가 시작하기 쉬운 32종 편집 목록을 둔다. 첫 12종은 바로 보이는 이미지 카드로, 나머지 20종은 같은 이미지 카드 형식으로 펼쳐 제공한다. 이는 인기 순위나 추천 결과가 아니며 선정 근거와 목록은 [`korea-familiar-breed-set.md`](korea-familiar-breed-set.md)에 기록한다.
- 일곱 생활 조건은 결과 옆에 계속 펼쳐 두지 않고 `생활 조건으로 좁히기` 버튼으로 여는 접근성 패널에 모은다. 전체 376종 검색·필터·URL 동기화·결과 복원은 유지한다.
- 첫 소개는 헤더 바로 아래에서 간결하게 시작하며 `이름을 몰라도 괜찮아요.` 제목을 홈의 검색 제목보다 낮은 크기로 표시한다. 제목·설명·검색창은 홈과 같은 중앙 정렬과 옅은 민트 방사형 배경을 사용하고 검색창은 최대 680px로 넓혀 필터 영역과 구분한다.
- 상단 검색이 화면 밖으로 지나가면 나타나는 고정 `견종 검색` 버튼과 검색 패널은 카드·헤더·스크롤 보조 버튼보다 높은 레이어에서 표시한다.
- 이미 이름을 아는 사용자를 위해 홈과 같은 대표 이미지 포함 한글명·영문명·별칭 자동완성 검색을 탐색 상단에 제공한다. `웰시 코기`·`웰시코기`는 통칭으로 인식해 웰시 코기 펨브로크를 우선하고 정확히 입력해도 바로 이동한다.
- 같은 축 안 OR, 서로 다른 축 AND 방식의 즉시 결과 갱신
- 체구는 소형·중형·대형·초대형 중 견종별 단일 값으로 분류한다. 초소형은 소형으로 묶고 범위·경계 표현은 상위 체구로 정규화하며, 상세의 출처 기반 cm·kg 범위는 별도로 유지한다.
- URL query 동기화, 선택 chip·개별 제거·`선택 지우기`
- 데스크톱 고정 필터는 일곱 기준을 저채도 물감색이 번지는 개별 카드로 구분한다. 모바일은 접근성 dialog 방식의 불투명 bottom sheet를 사용한다. 체구는 2×2, 나머지 세 단계 선택은 동일 폭 3열 버튼으로 정렬한다. 체구·활동량·정신적 자극·교감·독립성·주변 반응·털 관리 제목은 장식 아이콘 없이 짧은 물감 붓터치로 강조하고, 카드·선택 버튼·결과 배지가 기준별 같은 색을 공유한다. 검색 입력창을 제외한 필터·프리셋·결과 카드와 보조 UI는 컬러 외곽선 없이 배경 명도와 부드러운 그림자로 구분한다. 기준 안내 팝업은 결과 카드보다 위에 표시한다. 모바일 상단은 슬라이더 아이콘·`조건 필터`·선택 개수·`열기` 화살표를 한 실행 버튼에 묶는다.
- 탐색 결과 영역도 다른 주요 화면과 같은 최대 1440px 컨테이너를 사용한다. 데스크톱 카드는 최소 360px 폭을 확보하며 자동으로 열 수를 정해, 약 1400px 화면에서는 고정 필터 옆에 넉넉한 2열을 유지하고 더 넓은 화면에서는 3열로 확장한다.

- 비숑 프리제는 네 번째 공식 상세 기준 적용 견종이다. 프랑스와 벨기에에서 반려견으로 정립된 배경을 사람과 신호를 주고받는 참여와 매일의 산책·놀이로 연결하되 개체별 차이를 명시한다. 생활 현실 두 장은 짧고 성공적인 독립 휴식과 피부 가까이까지 살피는 곱슬 피모 관리다. 세 생활 질문과 말티즈·푸들 직접 이동 카드를 제공하며 기존 역사·학습·휴식·피모 자산 네 장과 새 야외 놀이 장면 한 장을 각각 한 의미로 사용한다.
- 후속 일괄 적용은 소형 반려견에만 맞춘 구조가 되지 않도록 디자이너 교배견·테리어·하운드·목양견·회수견·초대형 작업견을 포함한다. 각 견종의 기존 역할 단서와 현재 생활 카드, 관련 견종 이유를 재사용하되 연대 나열형 역사 원고를 공개 단계에 기계적으로 복제하지 않는다. 32종 전체의 표준 적용 여부와 각 상세의 서로 다른 로컬 이미지 다섯 장, 내부 출처 연결을 테스트로 보장한다.
- 두 번째 적용에서 `breed-detail-standard` 공용 구조·인터랙션과 Zod 편집 데이터 구조를 추출했다. 푸들의 네 크기 선택만 전용 모듈로 남으며, 이후 견종은 페이지 조건문을 늘리지 않고 공용 데이터와 필요한 선택 모듈을 추가하는 방식으로 전환한다.
- 상세 하단의 다음 선택 영역은 별도 배경 없이 `맞이할 준비하기` 한 행동을 제공한다. 푸들 시험 상세는 같은 회수견 배경 또는 소형 생활이라는 차이를 설명하는 작은 관련 견종 카드 두 개를 유지하며, 각 카드는 비교 화면을 거치지 않고 해당 견종 상세로 이동한다.
- 이름 속 견종과 호기심 탐험 화면도 탐색 탭·견종 카드·이미지 프레임에 컬러 외곽선을 사용하지 않고 배경 명도와 부드러운 그림자로 선택 상태와 카드 위계를 구분한다.
- 각 견종의 `careNotes`, 여섯 행동 경향, 보호자 맥락을 읽어 `먼저 챙길 세 가지`를 구성한다. 견종별 고정 그림 대신 12개의 정규화된 제품 아이콘을 의미에 맞춰 재사용한다.
- `먼저 챙길 세 가지`와 `생활에 가볍게 더하기`의 여섯 카드는 제목과 설명을 함께 분석해 아이콘을 배정하며, 같은 상세 안에서 아이콘이 반복되지 않는다. 성향 펼치기의 돋보기 속 발바닥 아이콘도 생활 카드에 다시 쓰지 않는다.
- 아직 기준 전환 전인 상세의 역사 영역은 역사 이미지 다음에 형성 배경과 오늘의 생활 연결을 두 문단으로 제공한다. 기준 상세는 독립 역사 영역 대신 01의 세 단계 흐름에서 배경을 다룬다. 상세의 별도 `이 강아지 성향 더 알아보기` 접기 영역은 상단 핵심 성향과 생활 카드의 반복이므로 표시하지 않는다. 여섯 성향 데이터는 견종 발견 필터와 편집 콘텐츠를 위해 그대로 유지한다.
- 맞이 준비 버튼은 설명을 살펴본 뒤의 선택 영역에 둔다. 저장된 가이드 진행 상태가 있으면 상세 CTA에 `계속하기` 또는 `확인 완료` 상태를 표시한다.
- 공통 상세의 큰 관련 견종 비교 블록은 표시하지 않는다. 푸들에만 2개의 작은 관련 견종 탐색 카드를 유지하며, 이는 추천이나 우열 비교가 아니라 다른 생활 조건의 상세를 바로 살펴보는 링크다.
- 크기와 평균 수명은 상세 화면에서 `cm`·`kg`·`년` 수치만 보여준다. 기관명·출처 주석·검토 상태 문구는 값에 섞지 않고 하단 출처 영역에 둔다. 연결된 근거에 표준 수치가 없는 항목은 임의 값을 만들지 않고 해당 행을 숨긴다.
- 국내 대표 표기는 `말티즈`이며 `몰티즈`는 검색 별칭으로 지원한다.

### 처음 함께 살기 가이드 `/beginner-guide?breed=[slug]`

- 데스크톱은 다른 주요 화면과 같은 최대 1440px 컨테이너를 사용하며, 첫 제목은 견종 상세보다 차분한 최대 3.4rem으로 표시한다.
- 재패니즈 스피츠에만 전체 적용 전 검수용 `맞이 준비도 진단` 시범판을 제공한다. 주거·시간·비용·가족·견종 이해 20문항을 한 화면씩 답하고, 100점 준비도와 별도의 필수 조건을 함께 판정한다. 결과는 적합성을 단정하지 않고 잘 준비된 부분·현재 걸리는 조건·다음 준비 항목을 보여준 뒤 기존 4단계 체크리스트를 연다. 다른 견종은 기존 가이드를 유지한다.

- 견종 적합성을 다시 판단하는 페이지가 아니라, 선택 이후 데려오기 전부터 첫 생활과 보호자의 마음가짐까지 필요한 최소 준비를 안내한다.
- `데려오기 전에 물어볼 것` → `첫날 꼭 필요한 것` → `첫 3일 함께 보내기` → `보호자로서 마음 준비하기` 네 단계를 순서대로 확인하며 다음 단계가 열린다.
- 로그인 없이 견종별 진행 상태를 브라우저 `localStorage`에 저장하고 상세 CTA에 반영한다.
- 마지막 단계는 모든 것을 미리 아는 대신 강아지를 계속 관찰하고, 보상 중심으로 가르치며, 평생 필요한 내용을 배워가는 책임을 확인한다.

### 비교 기능 상태

- `/compare`, 비교 후보 저장 상태, 전역 보관함, 상세 후보 버튼, 상단·모바일 비교 메뉴를 제거했다.
- 비교 기능은 현재 제품 범위에서 보류하며, 다시 도입하려면 목적과 읽기 구조를 새로 검토한다.

## 4. 디자인 현재 방향

- 분위기: 자연사 도감, 종이 질감, 현대적 반려동물 서비스의 중간 지점
- 색상: 아이보리 캔버스, 흰 패널, 짙은 잉크색 텍스트, 세이지·모스 계열 강조색
- 이미지: 성견의 견종별 비율을 목표로 한 전신 카드 삽화와 원래 역할·지역을 설명하는 역사 장면. 경주개 동경이 대표·역사 삽화는 호피무늬 단모와 짧거나 거의 없는 꼬리가 분명한 동일 개체 표현으로 교체했다. 생성·편집 일러스트의 파일 무결성과 실제 외형 승인은 별도 검수한다.
- 표현: 귀엽지만 유아적이지 않고, 장식보다 견종 실루엣과 정보 위계를 우선
- 레이아웃: 주요 콘텐츠와 헤더 모두 최대 1440px의 공통 컨테이너, 모바일 좌우 여백 16px 기준. 본문 텍스트는 내부의 더 좁은 읽기 폭을 유지한다.
- 접근성: 키보드 조작, 명시적 포커스, 충분한 대비, 최소 터치 영역, `prefers-reduced-motion`, 이미지 없이도 남는 핵심 정보

홈은 향후 전면 개편의 첫 시험으로 기존 세이지·모스 중심 화면과 분리한다. 흰색을 기본 면으로 두고 코코아 글자·오트밀 보조 면·절제된 캐러멜 행동색을 사용하며, 제목은 모바일 24px·데스크톱 28px 이내에서 끝낸다. 대표 3D는 무광 재질·부드러운 스튜디오 조명·실제 성견에 가까운 비율의 생활 디오라마로 한정하고, 내비게이션과 정보 UI는 평면적이고 익숙하게 유지한다. 다른 페이지의 색상·삽화 체계는 후속 개편 전까지 기존 상태다.

상세 규칙은 [`design-visual-guide.md`](design-visual-guide.md), 재사용 생활 아이콘은 [`product-icon-guide.md`](product-icon-guide.md), 현재 화면의 기반 설계는 [`redesign-v2.md`](redesign-v2.md)를 참고한다. 이전 보관함·비교 설계는 [`shortlist-design-spec.md`](shortlist-design-spec.md)에 역사 기록으로만 남아 있다.

## 7. 현재 알려진 문서 차이와 주의점

- [`mvp-scope.md`](mvp-scope.md)는 100종까지의 확장 기록을 담고 있으나 구현은 376개 상세 항목까지 진행됐다.

- 모바일의 견종 모아보기·이름 속 견종 결과는 정사각형 전신 이미지를 위에, 이름과 설명을 아래에 둔 작은 세로 카드 2열로 표시한다. 설명 높이에 이미지를 억지로 맞추지 않아 귀·발·꼬리의 잘림과 위·아래 빈 띠를 함께 피한다.
- 카드 상단의 견종 이미지는 위쪽 모서리만 둥글게 유지하고 아래쪽 모서리는 `0`으로 두어 설명 면과 끊김 없이 연결한다.
- 일본 스피츠 준비도 진단의 질문 이동 버튼 아래에는 `전체 질문 건너뛰고 결과 화면 보기`를 제공한다. 실제 응답을 저장하거나 결과로 오해하지 않도록 예시 답변으로 세 가지 결과 카드가 모두 보이는 미리보기임을 결과 상단에 명시한다.
- 비교 페이지는 소개 제목·견종명·비교 섹션 제목·생활 현실 카드 제목의 최대 크기를 한 단계 낮춘다. 모바일에는 더 낮은 글자 크기 상한을 적용하고 한국어 제목의 어절 단위 줄바꿈을 유지해, 이미지·비교 정보보다 제목이 과도하게 커 보이지 않게 한다.
- 비교 후보와 빈 상태 영역은 컬러 외곽선 없이 배경 명도와 부드러운 그림자로 구분한다. 후보가 없거나 한 마리만 있을 때의 제목과 안내는 한 문장씩 짧게 유지한다.
- `/discover` 결과 카드의 요약 표시는 `체구 · 중형`, `활동량 · 중간`처럼 항목명과 단계를 함께 보여준다. 필터 적용 중에는 해당 견종이 충족하는 선택 조건을 개수 제한 없이 모두 줄바꿈해 표시한다. 체구 외 여섯 성향 필터는 별도 점수나 수치 경계가 아니라 각 견종 원고의 `낮은 편·중간·높은 편` 편집 분류를 사용하며, 필터 패널의 기준 안내에서 각 축의 의미와 개체·환경에 따른 차이를 명시한다.
- `/discover` 결과 카드는 모바일의 둥근 모서리에서 밝은 선처럼 보이지 않도록 투명 테두리도 두지 않고, 카드 면과 부드러운 그림자로만 구분한다.
- 견종 상세 상단은 대표 이미지 옆에 한글·영문 이름, 2×2 핵심 정보 카드, 발견 필터와 같은 색의 3단계 성향 표시를 묶은 프로필 요약을 배치한다. 상세 페이지의 카드와 섹션은 컬러 외곽선 대신 배경 명도 차이와 부드러운 그림자로 구분한다.
- 견종 상세의 관련 견종은 원고에 직접 지정된 관계를 먼저 유지하고, 부족한 경우 같은 카탈로그 계통·공유 탐색 태그·생활 경향을 기준으로 보완해 대표 비교 외에 항상 카드 3개를 보여준다. 카드 이름은 한국어 제목 아래에 영어 이름을 별도 줄로 표시한다.

## 9. 다음 작업을 시작할 때 확인할 것

현재 저장소에 단일 확정 백로그는 없다. 다음 작업자는 요청 범위를 확인한 뒤 아래 순서로 판단한다.

1. 이 문서와 [`docs/README.md`](README.md)를 읽는다.
2. 작업 분야의 세부 명세와 최신 코드·테스트를 함께 확인한다.
3. 문서 속 과거 제안을 현재 구현으로 오해하지 않는다.
4. 제품이나 UI를 바꿀 때 단정적 추천, 적합도 점수, 승자 표현이 생기지 않는지 검토한다.
5. 기존 작업 트리 변경을 보존한다.
6. 변경을 검증하고, 범위·구조·수치·상태가 달라졌다면 이 문서를 함께 갱신한다.

## 10. 상태 문서 갱신 형식

이 문서는 작업 일지를 무한히 쌓는 곳이 아니다. 항상 ‘지금 사실인 것’만 유지한다.

- 상단 `마지막 갱신` 날짜를 바꾼다.
- 구현된 사용자 경험이 달라지면 3절을 수정한다.
- 디자인 시스템이나 주요 화면 방향이 달라지면 4절을 수정한다.
- 의존성, 데이터 흐름, 파일 경계가 달라지면 5절을 수정한다.
- 견종·자산·검수 수치가 달라지면 6절을 코드와 테스트에 맞춰 수정한다.
- 새로 발견한 불일치나 위험은 7절에 추가하고, 해결되면 제거한다.
- 실제로 실행한 최신 검증 상태는 8절에 기록한다.
- 결정의 역사와 이유가 중요하면 [`decisions.md`](decisions.md)에 별도 항목을 추가한다.
