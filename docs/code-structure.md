## 배치 규칙

- 기능 안에 컴포넌트, CSS Module, 로직, 테스트를 함께 둔다. 작은 기능에 불필요한 하위 폴더를 만들지 않는다.
- `app/`은 라우트를 구성하고 기능 코드를 가져온다. 기능이 `app/`의 컴포넌트나 스타일에 의존하지 않게 한다. 라우트 전용 스타일은 해당 라우트에 둘 수 있다.
- 여러 기능이 실제로 공유하는 UI만 `components/`에 둔다. 하나의 기능에서만 쓰면 그 기능 폴더에 둔다.
- 같은 폴더 안에서는 상대 경로, 기능 경계를 넘는 참조는 `@/` 경로를 사용한다. 경로 변경을 숨기는 호환용 재수출 파일은 만들지 않는다.
- `pet-tour-server.ts`는 서버에서만 사용한다. 클라이언트에서 서비스 키를 읽거나 서버 모듈을 가져오지 않는다.
- 견종 원고와 출처의 기존 배치 파일은 보존한다. 파일 이름만 보고 미사용 콘텐츠라고 판단하지 않는다.
- 테스트는 대상 파일 옆의 `*.test.ts`/`*.test.tsx`로 둔다. `src/app/`과 콘텐츠 검증도 기존 위치를 유지한다.

## 자산과 임시 파일

`public/`은 브라우저에 제공하는 자산이고, `design/`은 Blender 원본·제작 스크립트·프롬프트·검증 기록이다. 원본을 서비스 코드의 import 여부만으로 삭제하지 않는다.

`tmp/`에는 로컬 조사 결과·도구 런타임·검증 출력이 있다. Git에서 제외하지만 일괄 삭제하면 로컬 도구를 다시 설치해야 할 수 있다. `.next/`와 `node_modules/`도 코드 폴더 정리와 구분한다.

이미지 삭제 전에는 `pnpm audit:images`로 동적 콘텐츠 참조를 확인한다. 소스 이동 후에는 lint·typecheck·전체 테스트·프로덕션 빌드와 주요 화면을 확인한다. 이번 정리는 로컬 검증만 진행하며 커밋·푸시·배포는 포함하지 않는다.
