# Dog Atlas 프로젝트 현재 상태

> 마지막 갱신: 2026-08-14
> 역할: 제품·디자인·코드·콘텐츠·검증 상태를 빠르게 파악하기 위한 살아 있는 문서
> 갱신 책임: 중요한 변경을 수행한 사람 또는 AI가 같은 변경 안에서 이 문서를 함께 수정한다.

## 1. 한눈에 보기

Dog Atlas(살아 있는 견종도감)는 강아지를 고려하는 사람이 외모와 인지도만으로 선택하지 않도록 돕는 한국어 편집형 웹 도감이다. 사용자는 견종을 발견하고, 역사와 원래 역할이 행동 경향과 현대의 돌봄 요구에 어떻게 이어질 수 있는지 읽고, 관심 후보를 저장해 같은 기준으로 비교한다.

현재는 초기 5종 또는 100종 MVP 계획을 넘어 **370개 상세 항목과 시각 자산을 제공하는 로컬 데이터 기반 구현**까지 확장된 상태다. 마스터 카탈로그의 370개 항목 모두 상세 페이지가 있다. 등록단체 관계인 `registryStatus`와 도감의 편집 포함 근거인 `inclusionType`을 분리했으며, 골든두들과 말티푸는 등록 견종으로 오인되지 않도록 `designer-cross`로 표시한다.

## 2. 변하지 않는 제품 원칙

- 호기심과 따뜻함으로 사용자를 초대하고 책임 있는 판단을 돕는다.
- 견종 특성은 일반적 경향이며 개별 개체에 대한 보장이 아님을 밝힌다.
- 하나의 견종을 사용자의 정답으로 선언하지 않는다.
- 비교는 승자나 적합도 점수가 아니라 생활에서 체감할 차이를 이해시키는 데 사용한다.
- 입양을 미루거나 후보를 다시 검토하는 것도 유효한 결과다.
- 편집 초안을 수의학 또는 행동 전문가 검수 사실처럼 제시하지 않는다.
- 모바일 우선, 접근성, 빠른 로딩을 장식적 복잡성보다 우선한다.

## 3. 현재 구현된 사용자 경험

### 홈 `/`

- 첫 화면에서 370개 견종·교배견 정보, 생활 조건 탐색, 비교와 양육 정보라는 서비스 목적을 설명하고 `/discover`로 향하는 주요·보조 CTA를 제공한다.
- 새로 방문하면 첫 견종에서 시작하고, 첫 장은 읽을 시간을 조금 더 둔 뒤 이미지는 2초마다 교차 페이드하고 견종 설명 카피는 같은 600ms 안에서 이전 내용을 먼저 지운 뒤 다음 내용을 표시한다. 버튼·키보드·스와이프로도 조작할 수 있으며, 상세를 열었다가 브라우저 뒤로 돌아오면 직전에 보던 견종을 복원한다.
- CTA 아래에서 370개 항목의 한글명·영문명·등록 별칭을 검색한다.
- 견종 발견의 빠른 탐색과 같은 이름·필터를 공유하는 6개 생활 조건 아이콘 카드
- 모바일(767px 이하) 공통 하단에는 `홈`·`견종 발견`·`이름 속 견종`·`견종 모아보기`·`비교하기` 고정 내비게이션을 제공하고 safe-area와 관심 견종 tray 위치를 함께 보정한다. 다섯 메뉴는 지붕이 있는 집 안의 강아지, 돋보기 속 강아지 실루엣, 이름표 뒤 노바스코샤 덕 톨링 리트리버, 별을 보는 강아지, 서로 마주 보는 두 강아지의 단색 라인 아이콘을 사용한다.
- 생활 조건 아이콘은 카드와 별도 사각 배경이 생기지 않는 투명 WebP를 사용한다. 불독·보더콜리·카발리에 킹 찰스 스패니얼·시바 이누·휘핏·골든 리트리버를 각 조건의 대표 장면으로 그리되, 카드에는 견종 이름을 표시하지 않고 행동과 소품으로 조건을 구분한다.

### 이름 속 견종 `/breed-names`

- 대메뉴를 선택하면 별도 인덱스 없이 `Pointer` 상세(`/breed-names/pointer`)로 바로 진입한다.
- 상세 화면의 가로 주제 내비게이션에서 Retriever·Setter·Spaniel·Sheepdog/Shepherd·Terrier로 바로 이동한다.

### 견종 호기심 탐험 `/curiosity`

- 대메뉴를 선택하면 별도 인덱스 없이 기본 주제 `독특한 털` 상세(`/curiosity/distinctive-coats`)로 바로 진입한다.
- 상세 화면의 가로 주제 내비게이션에서 큰 체구·작은 체구·주름진 얼굴·이름 속 직업·도그쇼 이야기로 바로 이동한다.
- 데스크톱 헤더와 모바일 하단 내비게이션에서 두 편집 영역을 각각 독립된 대메뉴로 제공한다.

### 견종 발견 `/discover`

- 370개 항목을 체구와 여섯 개 tendency 축으로 필터링하는 독립 탐색 페이지
- 같은 축 안 OR, 서로 다른 축 AND 방식의 즉시 결과 갱신
- URL query 동기화, 선택 chip·개별 제거·`선택 지우기`
- 데스크톱 고정 필터 패널, 모바일 접근성 dialog 방식의 bottom sheet 필터. 모바일 상단은 필터와 선택 개수를 한 도구 막대로 묶고 빠른 탐색 프리셋은 동일 폭 2열로 정렬한다.
- 빠른 탐색은 홈과 공통으로 `느긋한 활동`·`많이 움직이기`·`사람과 교감`·`독립적인 성향`·`털 관리 적게`·`아직 잘 모르겠어요` 6개를 사용한다.
- 기존 `BreedVisual`을 사용하는 이미지 결과 카드. `/discover`는 생활 조건 필터와 결과 탐색에 집중하며 하단 역할·역사 섹션은 제거했다.
- 모든 370개 항목에 필터를 적용하되 첫 화면은 48개 카드만 렌더링하고 `견종 더 보기`에서 48개씩 추가한다.
- 상세를 보고 뒤로 오면 같은 URL 필터와 함께 `견종 더 보기`로 펼쳐 둔 결과 개수도 해당 방문 기록에서 복원한다.
- 빠르게 여러 조건을 누를 때도 최신 로컬 상태를 기준으로 URL을 합성하며, 모바일 sheet는 닫혀 있을 때 접근성 트리에서 제외하고 열릴 때 포커스 고정·Escape 닫기·배경 스크롤 잠금을 제공한다.

### 견종 상세 `/breeds/[slug]`

- 정체성, 형성 지역, 원래 역할, 역사 이야기
- 등록 상태와 분리된 도감 포함 유형 및 근거 기관 표시
- 행동 단서와 여섯 개 경향 축
- 오늘의 생활과 돌봄 현실, 하루 장면
- 관련 견종과 출처
- 관심 견종 저장·해제
- 선택을 마친 사용자는 `이 강아지 맞이할 준비하기` CTA에서 견종 이름을 이어받은 공통 초보 가이드로 이동한다. 저장된 진행 상태가 있으면 상세 CTA에 `계속하기` 또는 `확인 완료` 상태를 표시한다.

### 처음 함께 살기 가이드 `/beginner-guide?breed=[slug]`

- 견종 적합성을 다시 판단하는 페이지가 아니라, 선택 이후 데려오기 전부터 첫 생활과 보호자의 마음가짐까지 필요한 최소 준비를 안내한다.
- `데려오기 전에 물어볼 것` → `첫날 꼭 필요한 것` → `첫 3일 함께 보내기` → `보호자로서 마음 준비하기` 네 단계를 순서대로 확인하며 다음 단계가 열린다.
- 로그인 없이 견종별 진행 상태를 브라우저 `localStorage`에 저장하고 상세 CTA에 반영한다.
- 마지막 단계는 모든 것을 미리 아는 대신 강아지를 계속 관찰하고, 보상 중심으로 가르치며, 평생 필요한 내용을 배워가는 책임을 확인한다.

### 비교 `/compare`

- 저장하거나 URL로 전달한 2~3종 후보 비교
- 동일 기준의 행동·생활 정보 비교
- 모바일용 기준별 읽기 구조와 데스크톱 비교 구조
- 후보가 부족할 때의 빈 상태

### 전역 관심 견종 보관함

- 브라우저 `localStorage`에 최대 3종 저장
- 홈·상세·비교 화면 사이 상태 공유
- 저장 개수와 비교 가능 여부 안내

## 4. 디자인 현재 방향

- 분위기: 자연사 도감, 종이 질감, 현대적 반려동물 서비스의 중간 지점
- 색상: 아이보리 캔버스, 흰 패널, 짙은 잉크색 텍스트, 세이지·모스 계열 강조색
- 이미지: 성견의 견종별 비율을 목표로 한 전신 카드 삽화와 원래 역할·지역을 설명하는 역사 장면. 생성·편집 일러스트의 파일 무결성과 실제 외형 승인은 별도 검수한다.
- 표현: 귀엽지만 유아적이지 않고, 장식보다 견종 실루엣과 정보 위계를 우선
- 레이아웃: 일반 콘텐츠 최대 1200px, 비교 콘텐츠 최대 1440px, 모바일 좌우 여백 16px 기준
- 접근성: 키보드 조작, 명시적 포커스, 충분한 대비, 최소 터치 영역, `prefers-reduced-motion`, 이미지 없이도 남는 핵심 정보

상세 규칙은 [`design-visual-guide.md`](design-visual-guide.md), 현재 화면의 기반 설계는 [`redesign-v2.md`](redesign-v2.md), 보관함·비교는 [`shortlist-design-spec.md`](shortlist-design-spec.md)를 참고한다.

## 5. 코드와 아키텍처

- Next.js 16 App Router, React 19, strict TypeScript
- CSS Modules와 `src/app/globals.css`의 전역 CSS custom properties
- Zod 4로 로딩 시 검증하는 로컬 TypeScript 콘텐츠
- Vitest, Testing Library, jsdom 기반 테스트
- 데이터베이스, 인증, CMS, 외부 검색 엔진, 전역 상태 라이브러리 없음
- 공유할 필요가 없는 일시적 탐색 상태는 브라우저의 현재 history entry에만 저장하며, 새 방문이나 다른 URL 기록으로 전파하지 않음

## 7. 현재 알려진 문서 차이와 주의점

- [`mvp-scope.md`](mvp-scope.md)는 100종까지의 확장 기록을 담고 있으나 구현은 370개 상세 항목까지 진행됐다.
- [`catalog-20-proposal.md`](catalog-20-proposal.md)와 초기 디자인 명세의 ‘20종’ 표현은 역사적 계획이다.
- 이미지 프롬프트 배치 A·B 문서는 초기 15종의 제작 기록이며 전체 자산 제작 이력을 대표하지 않는다.
- 이미지 테스트 통과는 실제 외형의 정확성을 뜻하지 않는다. 기존 368종 카드는 1차 시각 점검했고, 삽살개를 포함한 22종에서 큰 불일치가 확인된 35개 자산을 공식·기관 자료에 맞춰 교체했다. 새 골든두들·말티푸 자산은 부모견 자료와 교배견 편차를 반영한 편집 초안이며 외형 전문가 승인 상태가 아니다. 상세 상태는 [`breed-visual-audit.md`](breed-visual-audit.md)를 따른다.
- 제품명은 코드 메타데이터에서 ‘살아 있는 견종도감’, 저장소와 문서에서는 ‘Dog Atlas’를 함께 사용한다.
- 아메리칸 핏불 테리어와 아메리칸 불리는 FCI가 아니라 UKC 등록 기준을 명시해 상세를 제공한다.

## 10. 상태 문서 갱신 형식

이 문서는 작업 일지를 무한히 쌓는 곳이 아니다. 항상 ‘지금 사실인 것’만 유지한다.

- 상단 `마지막 갱신` 날짜를 바꾼다.
- 구현된 사용자 경험이 달라지면 3절을 수정한다.
- 디자인 시스템이나 주요 화면 방향이 달라지면 4절을 수정한다.
- 의존성, 데이터 흐름, 파일 경계가 달라지면 5절을 수정한다.
- 견종·자산·검수 수치가 달라지면 6절을 코드와 테스트에 맞춰 수정한다.
- 새로 발견한 불일치나 위험은 7절에 추가하고, 해결되면 제거한다.
- 실제로 실행한 최신 검증 상태는 8절에 기록한다.
- 결정의 역사와 이유가 중요하면 [`decisions.md`](decisions.md)에 별도 항목을 추가한다.
