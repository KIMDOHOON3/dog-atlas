# 카드 WebGL 전환 — 2026-09-06

## 현재 구현

- 메인의 카드 이동은 WebGL 버텍스 셰이더가 20×28 격자(면당 1,120개 삼각형)를 휘게 한다. 다음은 위쪽부터 왼쪽으로 빠지고, 이전은 그 경로를 역행해 펴지며 위에 놓인다. 곡률에 맞춘 음영·빛·포일 색과 가장자리 알파 완화를 적용한다.
- 실제 HTML 카드 면의 계산된 스타일·그림·글을 준비 단계에서 텍스처로 캡처한다. SVG foreignObject는 DOM을 래스터화하는 중간 컨테이너이며, 카드 이동은 SVG/CSS 변형이 아니다. 원본 글자와 접근성 콘텐츠는 HTML에 유지한다.
- 전환 중에는 기본 포일 렌더러를 멈추고 전환 캔버스만 두 면을 그린다. 캔버스/컨텍스트는 기본 포일과 전환용 각 1개이고, 종료 시 전환 루프를 멈추고 HTML로 복귀한다. 유휴 상태에 계속 회전하는 별도 루프는 없다.
- 이동 820ms, 최대 60Hz. 정적인 격자와 셰이더를 재사용하며 루프 안에서 DOM 캡처·이미지 decode·텍스처 업로드를 하지 않는다. 전환 버퍼는 최대 110만 픽셀·DPR 1.5, GPU 텍스처는 LRU 4장이다. 390px 카드의 2배 텍스처 기준 약 13MiB이며 버퍼/드라이버 할당은 별도다.
- 현재/인접 텍스처를 미리 준비한다. 준비 중 중복 선택을 막고, 자료 준비가 끝난 뒤 전환 시간을 시작한다. 뒷면에서 선택해도 해당 뒷면이 빠지고 새 견종 앞면이 도착한다.
- reduced motion은 즉시 교체한다. WebGL/텍스처 캡처 실패는 기존 CSS 이동으로 대체한다. 탭 숨김·화면 밖·리사이즈·컨텍스트 손실은 목적지 HTML로 완료하며 언마운트 때 GPU 자원을 해제한다.

## 확인한 범위

- 실제 로컬 Chrome에서 8종 앞뒷면, 정방향/역방향, 390px, 포일 OFF, reduced motion 등 22개 전환을 확인했다. 개발 서버 측정: 전환별 rAF 간격 p95 최대 20.9ms, 전체 33.4ms 초과 간격 1회, JS draw 호출 최대 0.2ms. 오류 없음, 종료 후 캔버스 숨김/HTML 복귀, 캐시 4장 확인.
- Codex 인앱 브라우저의 프로덕션 메인에서 실제 버텍스 변형과 텍스처·이전 카드 복귀를 확인했다. 최종 전환 51프레임, rAF p95 20.8ms, 33.4ms 초과 0회였다. 텍스처가 준비된 상태에서 클릭 후 준비 시간은 2.00ms였다. 캐시 미스/초기 다운로드를 포함한 일반적인 입력 지연 보장은 아니다. lint·typecheck·1,646테스트·385페이지 빌드 통과.
- 이 수치는 CPU/rAF 관측이며 GPU 타이머나 실제 디스플레이의 표시 프레임 계측이 아니다. 실제 휴대전화/Safari/저사양 장치에서 동일 프레임률을 보장하지 않는다.
- 테스트는 GPU 준비 후 업로드 재호출 없음, 포일 중지, 고주사율 입력의 제출 한도, 컨텍스트 손실, 종료·자원 해제와 기존 fallback/reduced motion 조작을 포함한다.

## 수정할 때

카드 문구·이미지를 변경하면 새 페이지 로드에서 현재 DOM을 다시 캡처하므로 별도 이미지 재생성이 필요 없다. 캡처 코드는 `src/lib/card-texture.ts`, 변형/캐시는 `src/lib/card-transition.ts`, 조작/수명 관리는 `src/components/foil-card/foil-card.tsx`에 있다.

[MDN WebGL best practices](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices)의 버텍스 계산·버퍼 예산·텍스처 업로드 분리·자원 해제 지침을 참고했다.
