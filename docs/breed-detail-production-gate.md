# 새 견종 상세 제작·검수 게이트

> 적용 범위: 푸들 기준의 표준 상세를 새로 추가하는 모든 견종
>
> 상태: 2026-08-29부터 필수 적용
>
> 목적: 상세를 만든 뒤 대규모 재검수하는 시간을 줄이고, 조사·원고·이미지·화면 제작 과정 안에서 오류와 반복을 먼저 막는다.

## 1. 완료의 의미

새 상세는 데이터가 렌더링된 것만으로 완료되지 않는다. 아래 여섯 게이트를 모두 통과하고 기록을 남겨야 `편집 검수 완료`로 센다.

1. 이름과 견종 식별
2. 출처와 기본 수치
3. 견종 고유 원고와 자연스러운 한국어
4. 이미지의 외형 및 문장·장면 일치
5. 실제 화면·접근성 확인
6. 자동 검사와 검수 기록

이 게이트의 `편집 검수 완료`는 수의학·행동학·컨포메이션 전문가 승인을 뜻하지 않는다. 전문가 승인은 [`release-readiness.md`](release-readiness.md)의 별도 기록으로만 관리한다.

## 2. 제작 순서

기본 작업 단위는 한 견종이며, 같은 배치에 넣더라도 1~3종을 권장한다. 한 견종이 1~4단계를 통과하기 전에 다음 견종의 원고를 복제해 늘리지 않는다.

`식별 → 근거표 → 정보 설계 → 원고 → 이미지 → 코드 → 화면 검수 → 자동 검사 → 기록`

각 단계에서 실패하면 그 자리에서 수정한다. 배치 끝에 발견한 공통 문제를 여러 견종에 일괄 치환하는 방식은 견종 고유 내용을 지울 수 있으므로 사용하지 않는다.

## 3. 게이트 A — 이름과 견종 식별

- [ ] slug, 영문 등록명, 대표 한글명이 같은 견종을 가리킨다.
- [ ] 대표 한글명은 등록단체의 음역을 기계적으로 옮기지 않고 한국 사용자가 먼저 알아볼 통용명을 선택한다.
- [ ] 공식 음역, 과거 표시명, 띄어쓰기·철자 혼용과 국내 약칭은 `aliasesKo`에 남긴다.
- [ ] 공백과 하이픈을 생략한 검색어로도 같은 상세가 제안된다.
- [ ] FCI의 한 견종 내 바라이어티와 별도 등록 견종을 혼동하지 않는다.
- [ ] 토착견·랜드레이스·디자이너 교배견의 지위를 국제 등록견처럼 표현하지 않는다.

판정 기록에는 `대표명`, `유지한 검색 별칭`, `선택 근거 URL`을 적는다.

## 4. 게이트 B — 출처와 기본 수치

원고보다 먼저 견종별 근거표를 만든다. 최소한 다음 항목을 각각 어느 출처에서 확인했는지 기록한다.

| 항목 | 우선 근거 | 작성 규칙 |
|---|---|---|
| 등록·분류 | FCI 또는 해당 등록기관 | 정식·잠정·비등록 상태를 구분한다. |
| 형성 지역·역사 | 등록기관의 견종 역사, 국가기관 | 전승과 확인된 역사를 구분한다. |
| 과거 역할 | 역할을 직접 명시한 1차 자료 | 이름이나 그룹명만 보고 역할을 추정하지 않는다. |
| 현재 전문 역할 | 실제 운용기관 또는 공인 견종단체 | 현재도 수행한다는 직접 근거가 있을 때만 쓴다. |
| 체고·몸무게 | 공식 표준 또는 신뢰 가능한 국내 기관 | 단위와 대상이 같은 범위인지 확인한다. |
| 평균 수명 | 출처와 확인일이 있는 자료 | 근거가 약하면 임의 범위를 만들지 않는다. |
| 외형 | 공식 표준의 형태·피모·모색 항목 | 성견 기준으로 이미지 검수표를 만든다. |

### 국내 생활 경험 자료 대조

- [ ] 공식 표준만으로 드러나지 않는 국내 보호자의 생활 체감은 강형욱의 보듬TV `견종백과`처럼 국내에서 널리 소비되는 견종별 콘텐츠와 반복적으로 보고되는 보호자 경험을 추가로 대조한다.
- [ ] 영상 제목이나 진행자의 강한 표현은 관심 소재와 질문을 찾는 단서로 사용하고, 체고·역사·건강·행동의 확정 사실을 대신하는 1차 근거로 쓰지 않는다.
- [ ] 출연견 한 마리의 행동이나 댓글 한두 개를 견종 전체의 성격으로 일반화하지 않는다. 여러 자료에서 반복되는 생활 장면만 `나타날 수 있어요`라는 경향 문장으로 다룬다.
- [ ] 공식 자료와 국내 체감이 충돌하면 둘 중 하나를 감추지 않고, 공식적으로 확인되는 배경과 국내에서 크게 체감되는 조건을 구분해 적는다.
- [ ] 참고한 영상은 채널명, 영상명, URL, 확인일과 원고에 반영한 생활 질문을 견종별 제작 기록에 남긴다.

### 크기 수치 필수 규칙

- [ ] 상단 크기 카드는 모든 견종에서 `체고`와 `몸무게`의 같은 행 구조를 사용한다.
- [ ] `소형 · 약 25cm, 4kg` 같은 자유 문장을 상단 값으로 재사용하지 않는다.
- [ ] `cm`, `kg` 단위를 명시하고 범위 표기는 프로젝트 공통 형식인 `최솟값~최댓값`을 사용한다.
- [ ] 성별·크기·피모 바라이어티별 범위를 하나의 최소·최대값으로 뭉개지 않는다. 필요한 경우 펼침형 세부 정보를 제공한다.
- [ ] 체고와 몸무게 중 하나가 비어 있으면 편집 완료 전에 다른 공식 기관·원산국 단체·직접 연구 자료를 한 번 더 찾는다. 그래도 없을 때만 확인된 행만 표시하고, 미확인 이유를 견종별 기록에 남긴다.
- [ ] 국제 단일 표준이 없는 랜드레이스는 임의 범위를 만들지 않는다. 보존·연구 프로젝트의 실측 평균을 쓰는 경우 카드 안에 `프로젝트 평균`처럼 대상과 기준을 함께 표시한다.
- [ ] 두 출처가 다르면 측정 대상과 기준 차이를 먼저 설명하고, 편리한 숫자만 골라 섞지 않는다.
- [ ] 카드, 상세 데이터, 크기 비교 모듈에 같은 개념의 수치가 서로 다르게 들어가지 않았는지 검색해 확인한다.

## 5. 게이트 C — 견종 고유 원고와 한국어

### 먼저 정할 한 문장

글을 쓰기 전에 `이 견종을 다른 비슷한 견종과 구분하는 역사·작업 방식·생활 조건은 무엇인가?`에 한 문장으로 답한다. 이 문장이 세 단계 이야기와 생활 현실 두 항목을 선택하는 기준이다.

### 고유성 검사

- [ ] 과거 역할, 현재 경향, 생활 현실이 같은 사실을 표현만 바꿔 반복하지 않는다.
- [ ] `테리어라서`, `목양견이라서`, `리트리버라서`에 멈추지 않고 그 견종의 작업 대상·지형·거리·방식을 구체적으로 쓴다.
- [ ] 다른 견종 이름으로 바꿔도 문장이 자연스럽다면 다시 쓴다.
- [ ] 같은 배치의 다른 견종과 제목·본문을 나란히 놓고 공통 문장이나 동일한 결론이 반복되지 않는지 확인한다.
- [ ] 모든 개에게 해당하는 산책·사회화·휴식 안내를 견종 고유 특징처럼 넣지 않는다.
- [ ] 푸들의 크기, 닥스훈트의 체형처럼 실제 선택에 중요한 고유 조건만 전용 모듈로 만든다.

### 한국어 가독성 검사

- [ ] 영문 원문의 어순을 유지한 직역이 아니라 한국인이 한 번에 이해할 주어와 결론으로 다시 쓴다.
- [ ] 한 문장에는 결론 하나, 본문 한 블록에는 1~2문장만 둔다.
- [ ] `재지향`, `임계값`, `행동 종료`, `과제 전환` 같은 내부·번역 용어를 관찰 가능한 일상 장면으로 바꾼다.
- [ ] 추상적인 수식어보다 `무엇을 보고`, `어떻게 움직이고`, `보호자가 무엇을 준비하는지`를 쓴다.
- [ ] 강한 단정 대신 `나타날 수 있어요`, `개체마다 달라요`처럼 경향과 개체 차이를 함께 남긴다.
- [ ] 히어로 핵심 문장은 모바일 첫 화면에서 빠르게 이해할 수 있는 길이로 줄인다.
- [ ] 중요한 생활 조건은 제목과 첫 문장에 먼저 두고 긴 본문 끝에 숨기지 않는다.

## 제작 우선 확장의 상태 분리

300종까지 상세 골격을 먼저 만드는 배치는 스키마·직접 출처·크기 표현·고유 원고·이미지 존재 검사를 통과한 뒤에도 `production-draft`로 저장한다. 이 상태는 공개 경로에 연결된 제작 초안이며 `검수 완료`가 아니다.

- `production-draft`: 배치 자동 게이트와 장면별 기본 육안 확인을 통과했지만 한국어·모바일·배치 간 반복을 최종 편집 검수하기 전이다.
- `editorial-reviewed`: 아래 게이트 D~F와 이름·검색 검수를 모두 마친 내부 편집 완료 상태다. 견종발견 UI에는 이 상태를 노출하거나 필터링하지 않는다.
- 기존 상세는 상태 필드가 없으면 호환을 위해 `editorial-reviewed`로 읽되, 새 확장 데이터는 상태를 반드시 명시한다.
- 수의학·행동학·컨포메이션 전문가 검수는 두 상태와 별도로 기록한다.

## 6. 게이트 D — 이미지 외형과 문장·장면 일치

이미지를 예쁘게 만드는 일과 정확한 정보를 전달하는 일은 별개다. 이미지마다 아래 두 검사를 모두 통과해야 한다.

### 외형 검사

- [ ] 성견의 전체 체형, 머리, 귀, 꼬리, 다리, 피모와 대표 모색이 공식 범위 안에서 읽힌다.
- [ ] 비슷한 견종의 핵심 외형이 섞이지 않았다.
- [ ] 대표 카드와 역사·생활 장면의 개가 같은 견종으로 이어져 보인다.
- [ ] 극단적인 미용, 비만, 과도한 단두·주름·피모를 이상적인 대표 외형처럼 강화하지 않는다.
- [ ] 토착견·랜드레이스의 다양성을 하나의 쇼 타입으로 고정하지 않는다.

### 장면 싱크 검사

- [ ] 각 이미지는 제목과 본문의 핵심 행동 하나를 실제로 보여준다.
- [ ] 그림에 없는 물건·장소·행동·관리 조건을 대체텍스트나 본문이 주장하지 않는다.
- [ ] 역사 그림의 시대·장소·사람·작업이 확인된 배경과 충돌하지 않는다.
- [ ] 현재 경향 그림과 생활 현실 그림이 모두 `보호자 손짓 후 매트에서 쉼` 같은 장면으로 반복되지 않는다.
- [ ] 대체텍스트는 해석이 아니라 화면에 보이는 견종·장소·행동을 먼저 설명한다.
- [ ] 카드 크기와 390px 화면에서도 귀·꼬리·체형과 핵심 행동이 식별된다.

새 자산을 만들었다면 출처, 외형 단서, 전체 프롬프트, 최종 파일 경로와 수정 이유를 `docs/image-prompts-*.md`에 남긴다.

## 7. 게이트 E — 실제 화면과 접근성

최소 390px 모바일과 데스크톱 한 폭에서 실제 상세를 직접 읽는다.

- [ ] 대표명·영문명·히어로 문장과 체고·몸무게가 올바르게 보인다.
- [ ] 긴 이름과 수치가 겹치거나 부자연스럽게 한 글자씩 줄바꿈되지 않는다.
- [ ] 세 단계 탭과 모바일 가로 스크롤의 순서가 같고 모든 내용에 접근할 수 있다.
- [ ] 제목, 본문, 이미지의 시선 순서가 분명하며 중요한 정보가 장식보다 먼저 읽힌다.
- [ ] 이미지 잘림, 가로 넘침, 마지막 카드 여백, 하단 메뉴 겹침이 없다.
- [ ] 키보드의 Tab·방향키·Home·End와 체크박스 레이블이 동작한다.
- [ ] `prefers-reduced-motion`에서도 정보와 기능이 사라지지 않는다.
- [ ] 대표명과 최소 두 개의 혼용 별칭을 검색해 같은 상세로 연결되는지 확인한다.

## 8. 게이트 F — 자동 검사와 변경 기록

- [ ] Zod 스키마가 새 상세를 통과한다.
- [ ] slug, 관련 견종, 출처 URL과 이미지 경로 참조가 모두 유효하다.
- [ ] 대표명과 핵심 검색 별칭을 회귀 테스트에 추가한다.
- [ ] 견종 고유 역사 출처, 이미지 장면, 반복 방지 조건 중 회귀 위험이 있는 항목을 테스트로 고정한다.
- [ ] ESLint, strict TypeScript, 전체 Vitest, production build를 모두 통과한다.
- [ ] 브라우저에서 새 상세와 검색을 확인한다.
- [ ] 추가한 상세 수, 자산, 검수 범위와 검사 결과를 `project-status.md`에 기록한다.
- [ ] 새로운 편집 판단은 `decisions.md`, 이미지 제작 근거는 해당 프롬프트 기록에 남긴다.

## 9. 견종별 완료 기록 양식

```md
### [대표 한글명] (`[slug]`)

- 식별: [영문 등록명 / 등록 상태]
- 대표명: [대표 한글명]
- 검색 별칭: [별칭 1, 별칭 2, ...]
- 한 문장 구분점: [비슷한 견종과 구분되는 역사·작업 방식·생활 조건]
- 기본 수치: [체고 출처], [몸무게 출처], [수명 출처]
- 직접 역사·역할 출처: [URL]
- 외형 기준 출처: [URL]
```

## 10. 즉시 보류해야 하는 경우

다음 중 하나라도 해당하면 빈칸을 추정으로 채우지 않고 상세 추가를 보류한다.

- 대표 한글명과 견종 식별이 서로 다른 자료에서 충돌한다.
- 과거 역할이나 형성 배경을 뒷받침하는 직접 자료가 없다.
- 체고·몸무게 수치의 대상 또는 단위가 불분명하다.
- 기존 견종의 원고와 이미지만 바꿔 끼워도 구분되지 않는다.
- 그림이 공식 외형이나 실제 설명 장면과 명백히 충돌한다.
- 의료·행동 결론을 전문가 검수 없이 사실처럼 써야만 페이지가 성립한다.

보류는 실패가 아니다. 공개 품질을 지키기 위해 근거가 확보될 때까지 범위를 정확히 멈춘 상태다.
