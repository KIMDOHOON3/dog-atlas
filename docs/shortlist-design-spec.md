# 비교 후보 보관함 UX 명세

> 상태: 2026-08-23에 비교 기능이 현재 제품 범위에서 보류되며 구현이 제거되었다. 이 문서는 재도입 결정 전까지 현재 기능 명세가 아닌 역사적 설계 기록으로만 사용한다.

작성일: 2026-08-02  
적용 흐름: 홈에서 견종 발견 → 상세에서 후보 담기 → 후보 보관함 → 2~3종 비교  
적용 범위: PC·모바일 홈, 견종 상세, 전역 후보 보관함, 비교 빈 상태, 비교 페이지

## 1. 제품 원칙

이 기능은 사용자가 관심을 보인 견종을 잠시 보관하고 같은 기준으로 차이를 확인하게 돕는다. 사용자의 주거 환경이나 성격을 근거로 특정 견종을 추천하거나 적합 판정을 내리지 않는다.

- `나에게 맞는 견종`, `추천 결과`, `적합도`, `베스트 매치` 같은 표현을 사용하지 않는다.
- 저장은 입양 의사나 선호 확정이 아니라 `더 알아볼 후보`라는 뜻으로 다룬다.
- 비교에는 승자, 점수, 순위, 초록·빨강 우열 표시를 사용하지 않는다.
- 행동과 성격 정보는 견종의 일반적 경향이며 개체를 예측하거나 보증하지 않는다는 안내를 유지한다.
- 로그인 없이 바로 사용할 수 있어야 한다. 후보는 브라우저에 저장한다.
- 기존 `생활조건으로 다시 보기` 섹션과 관련 CTA·필터·결과 영역은 홈과 전체 흐름에서 완전히 제거한다.

## 2. 핵심 상태와 제한

### 2.1 후보 수

- 최소 저장 수: 0마리
- 보관함 노출 시작: 1마리
- 비교 가능 수: 2마리 이상
- 최대 저장 수: 3마리
- 같은 견종은 중복 저장할 수 없다.
- 후보 순서는 사용자가 담은 순서를 유지한다. 비교 페이지도 같은 순서로 시작한다.

최대 3마리는 구현과 인지 부담을 함께 고려한 제한이다. PC 비교표에서 `기준 + 견종 3열`을 유지할 수 있고, 모바일에서도 한 항목 안에 세 견종을 세로로 읽을 수 있다.

### 2.2 저장 방식

- MVP는 `localStorage`에 견종 slug 배열만 저장한다.
- 키 예시: `dog-atlas:compare-shortlist:v1`
- 로그인, 개인정보 입력, 서버 동기화는 요구하지 않는다.
- 저장값이 없거나 손상되면 빈 배열로 복구한다.
- 데이터에서 사라진 slug는 초기화 시 조용히 제거한다.
- 브라우저 저장소를 사용할 수 없는 경우 현재 탭의 메모리 상태로 동작하고, 최초 1회만 `이 브라우저에서는 후보가 방문 후 유지되지 않을 수 있어요.`를 알린다.

## 3. 전체 사용자 흐름

1. 홈에서 카드와 검색으로 견종을 발견한다.
2. 카드의 `자세히 보기` 또는 카드 자체를 눌러 상세 페이지로 이동한다.
3. 상세 상단에서 `비교 후보에 담기`를 누른다.
4. 첫 저장 직후 화면 하단에 후보 보관함이 나타난다.
5. 1마리일 때 보관함은 한 마리를 더 담아야 비교할 수 있음을 설명한다.
6. 상세의 관련 견종이나 홈으로 이동해 두 번째 후보를 담는다.
7. 2마리 이상이면 보관함의 비교 CTA가 활성화된다.
8. CTA를 누르면 저장된 2~3마리가 쿼리에 담긴 비교 페이지로 이동한다.
9. 비교 페이지에서도 후보를 뺄 수 있고, 1마리 이하가 되면 비교표 대신 안내 상태를 보여준다.

URL 예시: `/compare?breeds=japanese-spitz,samoyed`  
세 마리 예시: `/compare?breeds=japanese-spitz,samoyed,maltese`

## 4. 홈 화면

### 4.1 구조

1. 사이트 헤더
2. 히어로 문구와 검색
3. 발견용 대표 비주얼
4. `강아지 둘러보기` 카드 목록
5. 편집형 견종 큐레이션과 오늘의 강아지
6. 후보가 있을 때만 전역 후보 보관함

`생활조건으로 다시 보기`가 있던 위치는 다른 기능으로 채우지 않는다. 위아래 섹션 간 여백을 정리해 정보 밀도를 낮추고, 발견 카드와 편집 콘텐츠에 집중한다.

### 4.2 견종 카드

홈 카드 전체는 상세 페이지 링크다. 카드 내부에 별도의 후보 저장 버튼을 추가하지 않는다. 저장과 탐색 링크가 한 카드 안에서 경쟁하면 오조작이 늘고, 사용자가 정보 확인 전에 후보를 빠르게 수집하는 흐름이 되기 때문이다.

- 카드 제목: 견종명
- 보조 정보: 원산지 또는 계통 1개, 크기 범주 1개
- 카드 링크 접근성 이름: `{견종명} 자세히 보기`
- 카드 하단의 노출 카피: `자세히 보기`
- 이미 저장한 견종 카드에는 비상호작용 배지 `비교 후보에 담김`을 표시할 수 있다.
- 배지는 카드 제목 가까이에 두며 초록 체크나 성공 판정처럼 보이지 않게 모스 외곽선 형태로 사용한다.

### 4.3 헤더의 비교 링크

- 저장 0마리: `비교하기`
- 저장 1~3마리: `비교하기 · {n}`
- 헤더 링크를 눌렀을 때 후보가 2마리 이상이면 비교 페이지로 이동한다.
- 0~1마리면 비교 빈 상태 페이지로 이동한다. 모달로 막지 않는다.

## 5. 견종 상세 화면

### 5.1 PC 구조

상단 히어로의 정보 순서는 다음과 같다.

1. 브레드크럼
2. 견종 대표 비주얼
3. 견종명과 한 줄 소개
4. 원산지·크기·평균 수명 등 핵심 사실
5. 후보 저장 버튼
6. 행동 경향, 역사, 생활 현실, 건강·돌봄 정보
7. 관련 견종
8. 후보가 있을 때 전역 후보 보관함

저장 버튼은 견종명과 핵심 사실 다음에 둔다. 히어로 대표 이미지 위에 겹치거나 페이지 끝에만 두지 않는다.

### 5.2 모바일 구조

1. 브레드크럼
2. 견종명과 한 줄 소개
3. 대표 비주얼
4. 핵심 사실
5. 너비 100% 저장 버튼
6. 본문 정보
7. 관련 견종

하단 후보 보관함과 겹치지 않도록 페이지 마지막에 보관함 높이 + 안전 영역만큼 여백을 확보한다.

### 5.3 저장 버튼 상태와 정확한 카피

| 상태 | 버튼 카피 | 설명 |
|---|---|---|
| 저장 전 | `비교 후보에 담기` | 모스 채움 버튼 |
| 저장 완료 | `후보에서 빼기` | 패널 배경 + 모스 외곽선 |
| 처리 중 | `담는 중…` 또는 `빼는 중…` | 중복 입력 방지, 짧은 처리에 스피너는 생략 가능 |
| 최대 3마리 | `비교 후보에 담기` | 버튼은 누를 수 있으나 누른 뒤 교체 안내 제공. 미리 비활성화하지 않는다. |

저장 완료 후 라이브 안내:

- `{견종명}을 비교 후보에 담았어요.`
- 해제 후: `{견종명}을 후보에서 뺐어요.`
- 최대 도달 후: `비교 후보는 3마리까지 담을 수 있어요. 먼저 한 마리를 빼주세요.`

최대 도달 안내에는 현재 후보의 작은 목록과 각 `빼기` 버튼을 제공하는 보관함 확장 상태로 포커스를 이동하지 않고 열어준다. 사용자가 직접 기존 후보를 뺀 뒤 새 견종을 다시 담는다. 자동 교체하지 않는다.

## 6. 전역 후보 보관함

### 6.1 노출과 위치

- 후보 0마리: 렌더링하지 않는다.
- 후보 1마리부터: 홈과 상세 화면 하단에 고정한다.
- `position: fixed`로 뷰포트 하단에 두되 데스크톱은 중앙 정렬된 떠 있는 패널, 모바일은 화면 좌우와 하단에 밀착한 시트 형태다.
- 비교 페이지에서는 하단 보관함을 중복 노출하지 않는다. 비교 페이지 자체의 후보 헤더가 동일 기능을 담당한다.
- 쿠키 배너나 다른 하단 고정 UI와 동시에 사용하지 않는다. 필요하면 보관함이 위쪽 슬롯을 차지한다.

### 6.2 접힘 상태

PC 기본 높이: 88px  
모바일 기본 높이: 후보 1마리 84px, 후보 2~3마리 116~132px

후보 1마리:

- 제목: `비교 후보 1마리`
- 안내: `한 마리 더 담으면 같은 기준으로 비교할 수 있어요.`
- 비활성 CTA: `한 마리 더 담아주세요`

후보 2마리:

- 제목: `비교 후보 2마리`
- CTA: `2마리 비교하기`

후보 3마리:

- 제목: `비교 후보 3마리`
- CTA: `3마리 비교하기`

각 후보는 40~48px 정사각형 썸네일, 견종명, `후보에서 빼기` 아이콘 버튼으로 구성한다. 아이콘 버튼의 접근성 이름은 `{견종명} 후보에서 빼기`다.

### 6.3 확장 상태

- 후보명이나 `후보 목록 펼치기` 버튼을 누르면 패널이 위로 확장된다.
- PC에서는 최대 폭 안에서 후보 세 개가 가로로 보인다.
- 모바일에서는 후보가 세로 목록으로 보인다.
- 펼치기 버튼 카피: `후보 목록 펼치기`
- 접기 버튼 카피: `후보 목록 접기`
- `aria-expanded`와 `aria-controls`를 연결한다.
- 펼침 상태는 페이지 이동마다 기본 접힘으로 돌아가도 된다. 후보 데이터만 유지한다.

### 6.4 스크롤 동작

- 보관함은 첫 저장 후 아래에서 160ms 동안 12px 이동하며 나타난다.
- 스크롤 방향에 따라 숨기지 않는다. 사용자가 후보 상태를 잊지 않도록 계속 노출한다.
- 모바일 키보드가 열린 동안에는 보관함을 일시적으로 숨겨 검색 입력을 가리지 않는다. 입력이 끝나면 복귀한다.
- `prefers-reduced-motion: reduce`에서는 이동 없이 즉시 나타난다.
- iOS 안전 영역을 위해 `padding-bottom: env(safe-area-inset-bottom)`을 포함한다.
- 본문에는 접힌 보관함 실제 높이 + 24px만큼 하단 여백을 추가한다.

### 6.5 닫기와 전체 비우기

보관함 자체를 닫는 X 버튼은 제공하지 않는다. 닫기가 데이터 삭제인지 패널 숨김인지 모호하기 때문이다.

- 확장 상태에만 보조 버튼 `후보 모두 비우기`를 제공한다.
- 실행 전 확인 문구: `담아둔 비교 후보를 모두 비울까요?`
- 확인 버튼: `모두 비우기`
- 취소 버튼: `계속 담아두기`
- 완료 안내: `비교 후보를 모두 비웠어요.`

## 7. 비교 빈 상태와 부족 상태

### 7.1 후보 0마리

- 제목: `아직 담은 비교 후보가 없어요.`
- 설명: `관심 가는 견종의 정보를 읽고, 더 알아보고 싶은 견종을 후보에 담아보세요.`
- 주 CTA: `견종 둘러보기`
- 링크 목적지: 홈의 `강아지 둘러보기` 앵커

### 7.2 후보 1마리

- 제목: `한 마리를 더 담으면 비교할 수 있어요.`
- 설명: `{견종명}의 관련 견종을 살펴보거나 도감에서 다른 견종을 발견해보세요.`
- 주 CTA: `다른 견종 둘러보기`
- 보조 CTA: `{견종명} 상세로 돌아가기`
- 저장된 후보 카드에는 `후보에서 빼기`를 제공한다.

빈 상태에 임의의 인기 견종을 자동 선택하거나 `이 견종을 추천해요` 섹션을 넣지 않는다.

## 8. 비교 페이지

### 8.1 구조

1. 브레드크럼
2. 페이지 라벨 `견종 비교`
3. 제목 `관심을 가진 견종을 같은 기준으로 살펴보세요.`
4. 안내 `이 비교는 우열이나 정답을 정하지 않습니다. 일반적인 경향과 생활 부담을 함께 확인하세요.`
5. 비교 후보 헤더
6. 대표 비주얼 비교
7. 동일 기준 비교표
8. 가장 먼저 확인할 생활 차이
9. 비교 뒤에 남겨야 할 질문
10. CTA `다른 견종 더 발견하기`

### 8.2 비교 후보 헤더

- 각 견종의 썸네일, 이름, `후보에서 빼기` 버튼을 보여준다.
- 후보가 2마리 이상이면 헤더를 페이지 상단에 고정할 수 있다.
- sticky 헤더는 사이트 헤더 아래에 붙고 전체 높이는 PC 88px, 모바일 72px를 넘지 않는다.
- 모바일에서는 이름을 한 줄 말줄임하고 이미지 크기를 36px로 제한한다.
- 후보를 빼 1마리가 되면 비교표를 즉시 숨기고 1마리 부족 상태로 전환한다.
- 브라우저 뒤로가기로 되돌릴 수 있도록 후보 제거 자체는 URL을 `replace`하고, 페이지 진입·다른 화면 이동은 일반 `push`를 사용한다.

### 8.3 PC 비교 표현

- 2마리: `비교 기준 24% + 견종 각 38%`
- 3마리: `비교 기준 19% + 견종 각 27%`
- 표 전체 최소 폭은 880px이며 1440px 이상에서 1180~1360px 안에 둔다.
- 긴 문장은 행 높이가 늘어나도록 하고 고정 높이를 사용하지 않는다.
- 견종별 배경색으로 우열을 만들지 않는다. 열 구분에는 같은 명도의 중립 패널과 선만 사용한다.
- 화살표와 단계 표시는 `좋고 나쁨이 아니라 정도`라는 설명을 표 앞에 둔다.

### 8.4 모바일 비교 표현

767px 이하에서는 가로 스크롤 표 대신 기준별 카드 목록을 사용한다.

```text
[활동 요구]
재패니즈 스피츠  중간 · 규칙적인 산책과 놀이
사모예드          높음 · 긴 활동과 더위 관리
말티즈            낮음~중간 · 짧고 규칙적인 활동
```

- 기준명이 카드 헤더가 된다.
- 견종은 저장 순서대로 세로 배치한다.
- 이름, 정도 배지, 설명 순으로 읽힌다.
- 첫 4개 기준은 펼쳐 두고 나머지는 접을 수 있다.
- 접기 버튼은 실제 `button`과 `aria-expanded`를 사용한다.
- `모두 펼치기`, `모두 접기` 제어를 목록 상단에 제공한다.

## 9. 반응형 명세

### 9.1 360px

- 페이지 좌우 여백 16px
- 후보 보관함 좌우 8px, 하단 8px + 안전 영역
- 후보 썸네일은 겹쳐 보이는 36px 원형 또는 둥근 사각형으로 최대 3개 표시한다.
- 접힘 상태에는 후보명 전체를 나열하지 않고 `비교 후보 {n}마리`만 표시한다.
- CTA는 한 행 전체 너비이며 최소 높이 48px다.
- 확장 상태는 화면 높이의 70% 이하, 내부 목록만 스크롤한다.
- 비교 기준 카드는 1열이다.

### 9.2 361~767px

- 페이지 좌우 여백 20~24px
- 저장 버튼과 비교 CTA는 너비 100%
- 후보 보관함은 최대 폭 없이 화면 하단 시트로 사용한다.
- 600px 이상에서는 후보 썸네일과 CTA를 한 행에 배치할 수 있다.
- 비교는 기준별 카드 구조를 유지한다.

### 9.3 768~1439px

- 페이지 좌우 여백 32px
- 후보 보관함 폭: `min(calc(100% - 32px), 960px)`
- 상세 히어로는 이미지와 정보 2열을 유지하되 각 열 최소 폭을 320px로 둔다.
- 비교표는 2마리까지 기본 노출한다. 3마리일 때 뷰포트가 좁으면 표 영역에만 가로 스크롤을 허용한다.
- 스크롤 영역에는 키보드 포커스와 `좌우로 스크롤해 나머지 비교 내용을 확인할 수 있어요.` 안내를 제공한다.

### 9.4 1440~1919px

- 일반 콘텐츠 최대 폭 1200px
- 비교 콘텐츠 최대 폭 1440px
- 후보 보관함 최대 폭 1120px
- 후보명과 썸네일 세 개, 상태 안내, CTA를 한 행에 배치한다.
- 비교표의 3개 견종 열을 가로 스크롤 없이 노출한다.

### 9.5 1920px 이상

- 콘텐츠 폭을 더 늘리지 않는다. 일반 1200px, 비교 1440px 제한을 유지한다.
- 후보 보관함 최대 폭 1200px
- 넓어진 여백에는 장식이나 추가 추천 카드를 넣지 않는다.
- 본문 한 줄 길이는 최대 68ch를 유지한다.

## 10. 접근성

- 모든 저장·해제 동작은 `button`을 사용한다. 상세 이동은 `a`를 사용한다.
- 아이콘만 있는 해제 버튼에는 `{견종명} 후보에서 빼기` 접근성 이름을 제공한다.
- 저장 결과와 최대 제한 안내는 `aria-live="polite"` 영역에서 알린다.
- 전체 비우기 확인창은 제목과 설명이 연결된 접근 가능한 dialog로 만들고, 닫힐 때 실행 버튼으로 포커스를 돌린다.
- 보관함이 처음 나타나도 포커스를 강제로 이동하지 않는다.
- 비활성 비교 CTA는 `disabled`를 사용하고, 근처에 활성화 조건을 텍스트로 제공한다.
- 포커스 표시에는 기존 `--focus: #185dc0` 3px 외곽선을 유지한다.
- 일반 본문과 배경 대비는 4.5:1 이상, 큰 텍스트와 UI 경계는 3:1 이상을 확보한다.
- 터치 대상은 최소 44×44px, 주요 CTA는 최소 높이 48px다.
- 색상만으로 저장 여부나 정도 차이를 전달하지 않는다. 카피, 아이콘, 배지를 함께 사용한다.
- 후보 목록과 비교 항목의 DOM 순서는 시각적 순서와 같아야 한다.
- sticky 보관함이 브라우저 확대 200%에서 본문과 주요 컨트롤을 영구히 가리지 않아야 한다.
- 모션은 200ms 이하이며 `prefers-reduced-motion`을 따른다.

## 11. 기존 디자인과의 연결

### 11.1 색상

- 페이지 배경: `--paper: #f7f4ec`
- 패널 배경: `--panel: #fffdf8`
- 기본 글자: `--ink: #24302b`
- 보조 글자: `--ink-soft: #55615b`
- 선: `--line: #d9d4c8`
- 주요 CTA와 후보 수 배지: `--moss: #3f6653`
- 선택 보조 배경: `--moss-light: #dfece6`
- 경고·최대 상태는 빨강 대신 클레이 계열을 사용하되 텍스트로 이유를 함께 쓴다.

후보 보관함은 `--panel` 배경, `--line` 테두리, 기존 `--shadow`보다 약한 `0 10px 36px rgb(42 52 46 / 12%)` 그림자를 사용한다. 비교 후보를 초록색으로 채워 `정답`처럼 보이게 하지 않는다.

### 11.2 형태와 타이포

- 후보 보관함 데스크톱 반경: 22px
- 모바일 상단 모서리: 22px, 하단은 뷰포트 밀착 시 14px
- 썸네일 반경: 12px
- 제목과 버튼은 기존 `--font-sans` 700
- 안내 본문은 400~500, `line-height: 1.6`
- 보관함 제목 16px, 보조 문구 14px, CTA 15~16px
- 장식 일러스트는 추가하지 않는다. 썸네일과 견종명이 충분한 시각 앵커다.

## 12. 컴포넌트 경계 제안

- `ShortlistProvider`: 저장 상태, 최대 3마리 제한, localStorage 동기화
- `ShortlistToggle`: 상세 페이지의 저장·해제 버튼
- `ShortlistBadge`: 홈 카드의 `비교 후보에 담김` 상태
- `ShortlistTray`: 홈·상세의 전역 sticky 보관함
- `ShortlistItem`: 썸네일, 견종명, 해제 버튼
- `ShortlistLimitNotice`: 최대 도달 안내와 후보 목록
- `CompareEmptyState`: 0마리·1마리 상태
- `CompareCandidateHeader`: 비교 페이지 sticky 후보 헤더
- `ComparisonTable`: PC 2~3종 표
- `MobileComparisonList`: 모바일 기준별 카드 목록

한 개의 provider를 루트 레이아웃 가까이에 두고 카드, 상세, 헤더, 보관함이 같은 상태를 구독한다. 저장 버튼마다 별도의 로컬 상태를 만들지 않는다.

## 13. 상태별 수용 기준

- [ ] 후보가 0마리면 홈·상세에 보관함이 보이지 않는다.
- [ ] 첫 후보 저장 직후 하단 보관함이 나타나고 결과가 스크린리더에 안내된다.
- [ ] 후보 1마리에서는 비교 CTA가 비활성이고 이유가 보인다.
- [ ] 후보 2~3마리에서는 정확한 수를 포함한 비교 CTA가 활성화된다.
- [ ] 네 번째 후보를 담으려 하면 자동 교체 없이 최대 제한과 해결 방법을 보여준다.
- [ ] 상세, 헤더, 홈 배지, 보관함의 저장 상태가 즉시 일치한다.
- [ ] 새로고침 후에도 후보가 유지된다.
- [ ] 비교 URL로 직접 들어왔을 때 유효한 2~3개 slug를 복원한다.
- [ ] 비교 페이지에서 1마리 이하가 되면 표 대신 부족 상태가 보인다.
- [ ] 360px에서 보관함이 저장 버튼이나 본문 마지막 내용을 가리지 않는다.
- [ ] 767px 이하 비교가 가로 스크롤 없이 읽힌다.
- [ ] 1440px에서 세 견종 비교표가 한 화면 폭 안에 보인다.
- [ ] 1920px에서 본문 폭과 문장 길이가 과도하게 늘어나지 않는다.
- [ ] 모든 저장·해제·펼치기·비교 동작을 키보드만으로 완료할 수 있다.
- [ ] 화면 어디에도 적합도, 순위, 승자, 단정적 추천 표현이 없다.
- [ ] `생활조건으로 다시 보기` 섹션과 연결 CTA가 남아 있지 않다.
