# 견종별 3개 특징 카드 확장 명세

> 상태: **소규모 확장 진행**
> 마지막 갱신: 2026-08-20
> 현재 구현: 재패니즈 스피츠·말티즈·보더콜리 3종
> 남은 대상: 373개 상세 항목

## 1. 다음 작업자가 가장 먼저 알아야 할 것

- 사용자가 명시적으로 시작을 요청하기 전에는 다른 견종으로 확장하지 않는다.
- 장기 목표는 376개 모든 상세에서 기존 `함께 살기 전에` 중심의 공통 생활 카드 6개를 제거하고, 해당 견종을 이해하게 만드는 **견종별 3개 그림 카드**로 교체하는 것이다.
- 재패니즈 스피츠가 승인된 구조와 시각 기준의 파일럿이다. 다만 세 카드의 주제를 모든 견종에 그대로 복제하지 않는다.
- 각 견종의 세 카드는 서로 다른 사실을 전달해야 하며, 같은 페이지의 히어로·역사·비교 영역과 문장을 반복하지 않는다.
- 건강·유전질환 카드는 현재 범위에서 제외한다. 근거 수준과 전문가 검수 방식이 별도로 결정되기 전에는 빈칸을 채우기 위해 질환명을 만들지 않는다.
- 상세의 그림 카드 표시를 바꾸더라도 `breed.tendencies` 데이터는 삭제하지 않는다. 이 데이터는 `/discover` 필터와 비교 기능에서 계속 사용한다.

## 2. 현재 코드 상태

- 상세 라우트: `src/app/breeds/[slug]/page.tsx`
- 카드 스타일: `src/app/breeds/[slug]/page.module.css`
- 견종 데이터: `src/content/breeds/data.ts`, `src/content/breeds/detail-batch-*.ts`
- 견종 스키마: `src/content/breeds/schema.ts`
- 파일럿 이미지: `public/illustrations/v4/japanese-spitz-feature-*.webp`
- 파일럿 이미지 제작 기록: `docs/image-prompts-japanese-spitz-features-2026-08-19.md`

특징 카드 데이터는 `src/content/breed-features/`의 Zod 스키마와 로컬 데이터 모듈에서 slug로 조회한다. 페이지 내부에 견종별 배열을 추가하지 않는다.

권장 구조 예시:

```text
src/content/breed-features/
  schema.ts
  data.ts
```

카드 한 개의 최소 필드:

```ts
{
  eyebrow: string;
  title: string;
  description: string;
  image: string;
  alt: string;
  sourceUrls: string[];
}
```

`sourceUrls`는 화면 카드에 기관명을 노출하기 위한 필드가 아니라 편집 근거를 추적하기 위한 데이터다. 화면의 출처 목록과 중복 URL은 한 번만 표시한다.

## 3. 세 카드의 선정 기준

세 카드는 고정 카테고리가 아니라 해당 견종에 대해 사용자가 실제로 궁금해할 만하고, 근거 자료가 뒷받침하는 세 가지를 선택한다.

우선순위:

1. 사람과 관계를 맺는 방식이나 대표적인 기질
2. 원래 역할에서 이어지는 독특한 행동 경향
3. 실제 생활에서 크게 체감하는 관리·환경 부담

가능한 주제:

- 사람을 따르는 방식, 독립성, 낯선 사람과의 거리
- 알림 짖음, 추적, 몰이, 회수, 굴 파기, 후각 탐색
- 활동 리듬, 정신적 자극, 혼자 쉬는 방식
- 피모·털갈이, 더위·추위, 큰 체격이 만드는 공간 부담
- 체형이 아니라 그 체형 때문에 달라지는 실제 생활

선정하지 않는 주제:

- 히어로 이미지만 봐도 알 수 있는 단순 외모 설명
- `매일 산책이 필요해요`처럼 거의 모든 개에게 적용되는 조언
- 같은 페이지에서 이미 사용한 설명의 짧은 재작성
- 근거가 약한 성격 단정, 적합도 판정, 공격성 예측
- 대표 질환처럼 오해할 수 있는 건강·유전 정보

세 장을 고른 뒤 다음 질문에 모두 `예`라고 답할 수 있어야 한다.

- 이 견종이 다른 견종과 구별되는 이유를 하나 이상 알려주는가?
- 사용자가 함께 사는 모습을 구체적으로 상상할 수 있는가?
- 세 카드가 서로 다른 질문에 답하는가?
- 설명 없이 그림만 봐도 카드의 주제가 구분되는가?

## 4. 조사와 근거 사용 순서

1. 해당 견종의 현재 `Breed` 데이터, 출처, 역사, 성향, 관리 문구를 읽는다.
2. Google·Naver 검색 결과에서 반복되는 한국어 질문 주제를 확인한다. 자동완성이나 검색 결과 제목은 관심사 탐색용이며 사실 근거로 사용하지 않는다.
3. FCI·국가 켄넬클럽·공식 품종 클럽·등록기관의 표준과 안내에서 기질, 역할, 피모 등 사실을 확인한다.
4. 행동이나 관리 설명은 가능하면 공식 기관 또는 신뢰할 수 있는 수의·행동 자료로 교차 확인한다.
5. 검색 수요와 근거 자료가 모두 받쳐주는 주제를 우선한다.

검색량 원자료가 없는데 `가장 많이 검색한다`거나 정확한 순위를 단정하지 않는다. 블로그와 커뮤니티는 질문을 발견하는 자료로만 사용하며 사실의 최종 출처로 사용하지 않는다.

## 5. 카피 규칙

각 카드는 다음 위계를 사용한다.

- `eyebrow`: 사용자가 묻는 생활 주제, 2~8자 안팎
- `title`: 한 번에 이해되는 결론 한 문장
- `description`: 실제 상황 한 가지와 필요한 이해 또는 준비

좋은 예:

```text
짖음과 알림
작은 변화에도 먼저 반응할 수 있어요.
현관 소리나 창밖 움직임에 반응해 짖을 수 있어요. 짖음이 길어지지 않도록 소리가 들린 뒤 조용히 기다리는 연습을 어릴 때부터 해두면 좋아요.
```

피해야 할 표현:

- `공식 견종 표준에서는`, `자료에 따르면`처럼 카드 본문에서 출처를 해명하는 문장
- `기꺼이 참여합니다`, `소개됩니다` 같은 번역투
- `반드시`, `항상`, `절대로`, `완벽한 가족견` 같은 보장 표현
- `개체마다 달라요`만 덧붙이고 본문을 과도하게 단정하는 방식
- 전문용어만 나열하고 사용자가 무엇을 조심해야 하는지 알려주지 않는 설명

카드는 따뜻한 일상 언어로 쓰되 사실의 강도를 낮추기 위해 `~할 수 있어요`, `~하는 경향이 있어요`를 적절히 사용한다. 단, 모든 문장 끝에 같은 완충 표현을 반복하지 않는다.

## 6. 이미지 제작 규칙

- 카드마다 별도의 4:3 가로 편집 삽화를 만든다.
- 최종 파일은 1200×900 WebP를 기본으로 하고 합리적인 품질에서 용량을 줄인다.
- 저장 경로는 `public/illustrations/v4/<slug>-feature-<topic>.webp` 형식을 권장한다.
- 따뜻한 아이보리 종이, 옅은 세이지·베이지 수채 번짐, 섬세한 색연필 질감을 파일럿과 맞춘다.
- 성견의 실제 비율, 머리·귀·피모·꼬리·체형을 공식 외형 자료와 대조한다.
- 귀·발·꼬리가 카드 크롭에서 잘리지 않도록 넉넉한 안전 여백을 둔다.
- 텍스트·워터마크·카드 외곽선·과도한 상징을 이미지 안에 넣지 않는다.
- 세 장의 장면·자세·소품을 구분한다. 같은 전신 포즈에 소품만 바꾸지 않는다.
- 그림은 정보를 보조해야 하며 설명과 다른 행동을 보여주면 승인하지 않는다.

각 생성 배치는 `docs/image-prompts-<batch>.md`에 다음을 기록한다.

- 조사 근거와 선택한 세 주제
- 최종 카피
- 최종 프롬프트
- 출력 파일 매핑
- 외형·크롭·내용 일치 검수 결과

## 7. 구현 순서

한 번에 375종을 생성하거나 적용하지 않는다.

1. 사용자가 확장을 명시적으로 요청한다.
2. 배치 대상과 개수를 정한다.
3. 각 견종의 세 주제와 카피를 먼저 조사·검수한다.
4. 승인된 카피에 맞춰 이미지를 생성한다.
5. 이미지 외형과 장면을 확인하고 WebP로 최적화한다.
6. 로컬 데이터 모듈에 연결한다.
7. 데스크톱·모바일 카드 크롭과 제목 높이를 확인한다.
8. 테스트 후 배치 단위로 커밋·푸시한다.

첫 확장 배치에서는 재패니즈 스피츠 외 3~5종 정도로 데이터 구조와 제작 시간을 다시 검증하는 것이 안전하다. 사용자 승인 없이 배치 크기를 임의로 크게 늘리지 않는다.

## 8. 자동 검증 요구사항

확장 구현과 함께 최소한 다음 테스트를 둔다.

- 발행된 대상의 특징 카드가 정확히 3개인지 확인
- 세 카드의 제목·설명이 같은 견종 안에서 중복되지 않는지 확인
- 이미지 경로가 존재하고 WebP인지 확인
- 이미지 크기와 파일 용량 예산 확인
- `sourceUrls`가 비어 있지 않고 해당 견종 출처와 연결되는지 확인
- 카드 설명이 같은 페이지의 역사·성향·관리 문구와 완전히 동일하지 않은지 확인
- 특징 카드 추가 전후 `/discover` 필터 결과가 변하지 않는지 확인

배치마다 변경 파일 ESLint, TypeScript, 관련 테스트를 실행한다. 가능하면 프로덕션 빌드를 한 번 실행하고, PC·모바일에서 이미지 크롭과 카드 높이를 확인한다.

## 9. 현재 파일럿의 최종 상태

재패니즈 스피츠의 세 카드는 다음과 같다.

1. 사람과의 관계 — 보호자와 산책하거나 놀이하는 시간을 즐기는 경향
2. 짖음과 알림 — 현관 소리나 창밖 움직임에 반응할 수 있고 짖음이 길어지지 않도록 연습이 필요한 점
3. 털 관리 부담 — 풍성한 이중모와 털갈이 시기의 규칙적인 빗질

상세의 별도 `이 강아지 성향 더 알아보기` 아코디언은 반복 정보라서 제거됐다. 상단 핵심 성향은 유지하며, 여섯 `tendencies` 원본 데이터도 필터와 비교를 위해 유지한다.

첫 확장 대상으로 말티즈를 추가했다. 세 카드는 사람과 가까이 지내는 방식, 작은 체구에 맞는 생활 안전, 길고 곧은 흰 피모의 반복 관리를 다룬다. 제작 근거와 프롬프트는 [`image-prompts-maltese-features-2026-08-20.md`](image-prompts-maltese-features-2026-08-20.md)에 기록했다. 말티즈의 준비 가이드는 기존 체크리스트를 유지하며 재패니즈 스피츠 준비도 진단을 확장하지 않았다.

두 번째 확장 대상으로 보더콜리를 추가했다. 세 카드는 움직임을 읽는 몰이 행동, 빠른 학습에 맞는 협력 과제, 활동 뒤 차분히 쉬는 리듬을 다룬다. 제작 근거와 프롬프트는 [`image-prompts-border-collie-features-2026-08-20.md`](image-prompts-border-collie-features-2026-08-20.md)에 기록했다.

## 10. 완료 조건

전체 확장은 다음 조건을 모두 만족해야 완료로 기록한다.

- 376개 상세 모두 견종별 3개 카드가 있다.
- 기존 공통 생활 카드 6개 렌더링은 제거됐다.
- 총 1,128개 카드 이미지가 로컬 경로와 편집 기록을 가진다.
- 페이지 내 반복 문구와 같은 견종 내 중복 주제가 없다.
- 건강 정보가 근거 없이 특징 카드에 섞이지 않는다.
- `/discover` 필터와 비교 기능이 기존 성향 데이터를 그대로 사용한다.
- 반응형 화면, 접근성, 자산 용량과 전체 빌드가 검증됐다.
