# iOS 카드 렌더링 보완 — 2026-09-12

사용자가 제공한 약 39초 iPhone 화면 녹화에서 카드 그림/글이 하얗게 날아가고, 견종 이동 중 카드 면이 좌상단에 작게 붙으며, 검색 입력 뒤 화면이 확대되어 좌우가 잘리는 현상을 확인했다. 원본 영상과 분석용 추출 이미지는 저장소에 포함하지 않았다.

## 변경

- `card-foil.ts`: 포일 RGB에 최종 알파를 곱하고 `premultipliedAlpha: true`를 사용한다. 기존 비선곱 알파 캔버스는 WebKit의 [합성 오류 200026](https://bugs.webkit.org/show_bug.cgi?id=200026)와 일치하는 경로였다. 이 WebKit 수정이 사용자의 iOS에 포함됐다고 가정하지 않는다.
- `card-transition.ts`: 셰이더 출력을 선곱 알파로 바꾸고 `ONE / ONE_MINUS_SRC_ALPHA`로 두 카드 면을 합성한다. 기존 일반 `blendFunc(SRC_ALPHA, ...)`의 알파 제곱도 제거된다. 색 채널을 알파 이하로 유지하는 [WebGL 합성 규칙](https://registry.khronos.org/webgl/specs/latest/1.0/)에 맞춘다.
- `card-texture.ts`: SVG와 foreignObject의 크기를 실제 CSS px와 동일하게 유지하고, 최종 2D 캔버스에서만 2배 래스터를 만든다. 스냅샷에 불필요한 `will-change`, containment를 제거한다. WebKit의 [foreignObject 위치/크기 문제](https://bugs.webkit.org/show_bug.cgi?id=23113)를 피하기 위한 변경이다.
- 카드의 불투명 종이 배경을 내부 9개 지점에서 검사한다. 빈 화면이나 좌상단에만 그려진 캡처는 GPU 텍스처로 업로드하지 않는다. 이 오류를 감지한 세션에서는 기존 HTML 카드 이동을 사용하며 계속 같은 캡처를 재시도하지 않는다. 정상 브라우저의 WebGL 곡면 이동과 4장 캐시·유휴 정지는 유지한다. 배경 검사는 모든 내부 글자/그림의 시각적 정확성을 판정하는 검사는 아니다.
- 검색창은 모든 크기에서 16px를 유지한다. 포인터로 검색 결과를 선택하면 입력을 다시 포커스하지 않으며, 키보드 선택은 `preventScroll`로 포커스를 돌려준다. 사용자 핀치 확대를 제한하는 viewport 설정은 추가하지 않았다.

## 검증

- 로컬 Chromium 390px: 포일 색/가독성, 앞면→다음, 뒤집기→뒷면→다음, 프렌치 불도그 검색과 분류 변경, 선택 뒤 입력 포커스 해제를 확인했다. 320px 역방향과 1440px 정방향도 확인했다. 세 폭 모두 페이지 가로 넘침 없음, 입력 폰트 16px. 정상 캡처에서 WebGL 전환이 사용되고 텍스처 캐시는 최대 4장이었다.
- 회귀 테스트: 1:1 SVG→2배 래스터, 빈/좌상단 캡처 거부, 준비 실패 시 HTML 전환 완료, 포인터/키보드 선택 후 포커스 동작. 전체 54개 파일/1,667개 테스트 통과.
- lint·TypeScript 별도 검사·385페이지 프로덕션 빌드 통과. 로컬 브라우저 콘솔 오류 0건.
- `a8b268b`를 main에 푸시한 뒤 공개 사이트 HTTP 200과 새 수정 문자열을 포함한 JavaScript 번들 제공을 확인했고, 배포 메인 페이지를 브라우저에서 열었다.
- 실제 iOS/WebKit 실행 환경은 이번 작업에서 사용할 수 없었다. 사용자 영상 분석·관련 WebKit 버그·코드 경로를 바탕으로 수정했으며, 실제 iPhone에서 증상 소멸이나 FPS를 확인했다고 표현하지 않는다.
