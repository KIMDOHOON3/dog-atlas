## 사용자와 확정한 상세 방향

- 푸들은 복사할 문장 템플릿이 아니라 정보 흐름과 시각 품질의 기준이다.
- 각 견종은 `과거의 실제 역할 → 오늘 할 수 있는 안전한 대체 활동 → 활동 뒤 회복 → 함께 살 때 체감하는 구체적 현실 → 피모·귀·발 등 실제 관리`가 한 흐름으로 이어져야 한다.
- 테리어·하운드처럼 같은 그룹이어도 공통 문장을 돌려 쓰지 않는다. 그 견종만의 역사, 움직임, 집에서 체감하는 특징을 짧고 직관적인 한국어로 쓴다.
- 대표 이미지, 역사 이미지, 카드 원고와 생활 장면은 같은 견종 외형과 의미를 가리켜야 한다.
- 생활 이미지는 푸들 상세처럼 따뜻한 수채화·색연필·종이결의 2D 그림으로 만든다. 3D 디오라마, 사진풍, 확대된 신체 클로즈업, 같은 개의 복제, 여러 마리, 의미 없는 훈련 코스는 쓰지 않는다.
- 한 장에는 성견 한 마리의 전신이 자연스럽게 보여야 한다. 도구와 배경은 원고를 한눈에 이해시키는 데 필요한 만큼만 둔다.
- 한국인이 바로 읽히는 견종명과 문장을 우선하고, 공식 표기는 검색 별칭으로 보존한다.
- 크기 카드는 공식 근거가 있는 체고·몸무게만 사용한다. 성별·유형·허용 오차는 펼침 정보로 분리하며 없는 몸무게를 추정하지 않는다.

## 한 묶음의 작업 순서

1. `docs/project-status.md`, `docs/product-brief.md`, `docs/mvp-scope.md`, `docs/decisions.md`, `docs/design-visual-guide.md`, `docs/breed-detail-standard.md`, `docs/breed-detail-production-gate.md`를 읽는다.
2. 기존 카드·역사 이미지·대표 이미지와 상세 초안을 먼저 본다. 맞는 것은 유지하고, 견종 외형이나 역할이 틀린 것만 교체한다.
3. FCI·AKC·UKC 등 공식 1차 자료로 역할·크기·외형을 대조한다. 국내 체감 표현은 사실을 과장하지 않는 범위에서 보조 자료로만 사용한다.
4. 네 생활 장면을 서로 다른 의미로 설계하고, 이미지 생성 전에 각 장면이 어느 문장을 설명하는지 적는다.
5. 이미지 생성 결과를 한 장씩 직접 보고 외형, 단일 개체, 전신, 2D 수채화, 원고 싱크를 확인한다. 통과하지 못한 시안은 연결하지 않는다.
6. 데이터와 자산을 연결하고 해당 세 종만 `paused3dStandardBreedSlugs`에서 제거한다.
7. ESLint, TypeScript, 전체 테스트, 프로덕션 빌드를 실행하고 `docs/project-status.md`와 이미지 제작 기록을 갱신한다.
