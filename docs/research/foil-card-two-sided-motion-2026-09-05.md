# 양면 포일과 손으로 넘기는 카드 모션

사용자는 뒤집을 때 렉을 보고했고 뒷면에도 앞면 효과를 요청했다. 이어서 단순 회전이 평범하다며 더 개성 있는 전환을 요청했다.

## 변경

- 기존 기울기를 0으로 즉시 바꾸던 처리를 제거한다. 480ms 동안 최대 10px 위로 들어 올리고 4도 비스듬히 틀며 3.5% 확대했다가 부드럽게 복귀한다. 앞→뒤와 뒤→앞의 방향이 반대이며 얇은 옆면에서 정적 빛 띠의 opacity만 짧게 올린다.
- 큰 그림 두 장을 preserve-3d 계층에서 동시에 회전시키는 대신 같은 평면의 한 면만 표시한다. 90도 부근에서 활성 HTML 면을 바꾸고 나머지는 hidden으로 제외한다. 기울기와 전환을 하나의 약 60Hz 루프에서 처리해 별도 CSS 전환과 충돌하지 않는다.
- 캔버스/WebGL 컨텍스트/텍스처를 하나만 유지한다. 화면에 보이는 면이 같은 셰이더를 공유하며 back uniform은 뒷면 상단·왼쪽 수치·하단 글에 포일이 강하게 덮이지 않도록 한다. 양면에서 드래그/방향키/시연/강도/끄기를 사용할 수 있다.
- 회전 중에는 포일을 동결하고 면 교체와 착지 때 갱신한다. 정상 준비 상태의 회귀 테스트에서 전환당 최대 2회 제출을 확인했다. 일반 움직임은 기존 약 30Hz·너비 320 상한, idle/hidden/offscreen/off 중지와 GPU 정리를 유지한다.
- 뒷면 이미지를 eager 로드하고 두 이미지의 decode를 미리 요청한다. 신규 그림·3D 라이브러리·이미지 해상도 하향은 없다.
- 연속 클릭은 착지까지 합쳐 1번만 전환한다. 드래그와 탭 구분, 활성 면 접근성, WebGL 없는 전환, reduced motion 즉시 전환을 유지한다. 탭 숨김/화면 밖/컨텍스트 손실/움직임 줄이기 변경 시 전환을 완료 상태로 정리한다.

## 확인과 한계

로컬 Codex 브라우저, 개발 서버 `?profile=1`의 1회 새 전환: 30회 렌더 샘플, 프레임 간격 p95 16.8ms, 33.4ms 초과 0회. 뒷면 4.4초 시연: 264개 간격, 포일 132회, 평균 16.67ms·p95 16.8ms, 캔버스 320×453. 이는 rAF 스케줄/그리기 요청이며 실제 GPU 시간·모든 사용자 기기의 FPS 개선률이 아니다. 기존 사용자 렉의 실기기 원인을 재현하거나 단일 원인으로 확정한 것은 아니다.

데스크톱에서 새 전환 중간 자세·양면 전환·뒷면 포일/시연, 390px에서 뒷면 드래그와 앞면 복귀를 확인했다. 모바일 viewport의 복귀 전환도 30샘플/p95 16.8ms/33.4ms 초과 0이었다.

lint·typecheck·57파일/1,656테스트·403페이지 프로덕션 빌드 통과. 테스트는 기존 기울기 유지, 연타 합치기, 단일 캔버스/renderer 재사용, 전환 최대 2회 포일 제출, 뒷면 조작/끄기/복귀, 드래그 판별, reduced motion과 WebGL 대체 상태를 포함한다. 3000/3001에 최종 빌드를 반영하고 기존 3001 탭에서 새 전환·뒷면 시연·재질 로딩 완료·너비 320·브라우저 오류/경고 없음, HTTP 200/캔버스 1개를 확인했다. 사용자 기기의 렉 개선과 새 모션의 선호도는 재평가가 필요하다.
